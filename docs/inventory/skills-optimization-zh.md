# Skills 第一性原理精简审计

本文覆盖 `manifests/skills.json` 声明的 30 个 skill。分析口径：每份 skill 只保留让 agent 更可靠完成任务所必需的触发、流程、输出、验证和禁止项；技术标识、命令、路径、包名和协议字段不翻译。

| Skill | 当前职责 | 第一性原理 | 主要冗余 | 精简方案 | 优先级 |
| --- | --- | --- | --- | --- | --- |
| `brainstorming` | 把想法收敛为实现前设计。 | 防止未澄清意图就实现。 | 反模式和视觉伴侣说明重复。 | 保留硬门禁、提问、方案和规格交付；视觉细节放辅助文档。 | 高 |
| `api-and-interface-design` | 设计稳定 API 与模块接口。 | 接口一旦发布就会形成外部依赖。 | REST/TS 示例和原则解释偏长。 | 保留契约、兼容、边界校验和变更检查；示例压成最小模式。 | 高 |
| `writing-plans` | 将规格转成可执行实现计划。 | 计划必须让执行者无需自行决策。 | 反复强调执行者无上下文。 | 保留文件结构、任务模板、无占位和自审规则。 | 高 |
| `test-driven-development` | 约束先测试后实现。 | 未见测试失败就无法证明测试有效。 | 大量说服性段落。 | 保留 red-green-refactor、红旗和完成检查；反模式移入辅助文档。 | 高 |
| `systematic-debugging` | 在修复前定位根因。 | 没有根因的修复只是猜测。 | 现实影响和重复警告偏多。 | 保留四阶段流程、辅助资料入口和根因输出格式。 | 高 |
| `verification-before-completion` | 完成声明前收集新鲜证据。 | 结论必须由当前输出支持。 | 多组相同警告重复。 | 合并为硬门禁、证据表、红旗和汇报格式。 | 高 |
| `code-review-and-quality` | 多维度审查代码变更。 | 审查要发现会影响代码健康的风险。 | 团队协作通识偏多。 | 保留五轴、流程、发现格式、大小和依赖检查。 | 高 |
| `requesting-code-review` | 组织审查请求上下文。 | 审查质量受输入上下文限制。 | 长示例可模板化。 | 固定目标、范围、风险、验证和重点关注模板。 | 中 |
| `task-intake` | 粗略请求转任务启动块。 | 实现前必须知道目标和停止条件。 | 已很短。 | 保持短清单，只统一中文术语。 | 中 |
| `workflow-packet` | 判断 workflow 档位并收集证据。 | 风险分级决定验证强度。 | 已很短。 | 保留升级优先和不得降级 Full 工作流。 | 高 |
| `workflow-handoff` | 暂停或转交工作上下文。 | 下一位执行者不能靠猜继续。 | 可进一步字段化。 | 固定目标、已做、未做、验证、风险和下一步。 | 中 |
| `api-contract-check` | 实现前核对外部契约。 | 字段和权限不能由前端臆造。 | 已接近最小。 | 保留契约来源、字段、mapper、阻塞项和验证五步。 | 高 |
| `frontend-implementation-check` | 检查 UI 实现完整性。 | UI 正确性必须覆盖状态和真实浏览器。 | 易与 frontend rules 重复。 | 聚焦页面状态、响应式、数据流和浏览器验证。 | 中 |
| `task-decomposition` | 将大任务拆成可验证子任务。 | 小任务降低上下文和回滚成本。 | 可压成操作清单。 | 保留 parent/child、5 分钟目标、停止条件、验证和写入范围。 | 中 |
| `worktree-mergeback-check` | 检查 worktree 合并回主线。 | 临时环境通过不代表最终环境通过。 | 已较短。 | 保留隔离、dirty 状态、最终位置验证和清理计划。 | 中 |
| `loop-planning` | 规划受控 loop。 | 循环必须有 ledger、停止条件和判定来源。 | 已精简。 | 只统一 metadata 和术语。 | 低 |
| `review-checklist` | 独立审查 diff 和 workflow 合规。 | 审查必须优先发现风险。 | 已精简。 | 只统一 metadata 和术语。 | 低 |
| `release-checklist` | 发布、回滚和部署门禁检查。 | 生产变更必须可验证、可回滚。 | 可避免复述 release rules。 | 保留版本、环境、回滚、验证和确认项。 | 中 |
| `pencil-design-check` | 检查 Pencil 设计资产交付。 | 加密设计源必须走专用工具链。 | 已较短。 | 保留 `.pen`、预览、设计系统边界和交付证据。 | 中 |
| `agentmemory` | agentmemory 子技能入口说明。 | 记忆能力应按具体意图路由。 | 入口无需长文。 | 保持极短，列出子技能分工。 | 低 |
| `handoff` | 从记忆恢复最近相关 session。 | 恢复应选择最相关上下文并重新验证。 | 原触发描述英文。 | 中文化并保留候选选择、摘要和验证边界。 | 中 |
| `recall` | 搜索历史记忆。 | 历史记忆是线索，不是事实。 | 操作步骤可短化。 | 保留查询词、排序、来源和当前状态复核。 | 中 |
| `remember` | 保存耐久项目记忆。 | 只保存未来会复用的信息。 | 可明确不保存范围。 | 区分可保存与不可保存内容。 | 中 |
| `forget` | 删除指定记忆。 | 删除是破坏性操作，必须明确对象。 | 原文可字段化。 | 保留确认、候选、删除范围和误删防线。 | 高 |
| `recap` | 汇总近期 session。 | 摘要应突出可行动信息。 | 避免流水账。 | 保留检索、合并、完成/未完成、风险。 | 中 |
| `session-history` | 列出近期 session。 | 用户需要选择上下文，而非完整摘要。 | 已短。 | 保持短查询技能。 | 低 |
| `commit-history` | 展示 commit 与 session 关联。 | 代码历史需要可追溯解释。 | 已短。 | 保留 hash、信息、时间和复核提示。 | 低 |
| `commit-context` | 追溯文件/符号/行到 commit 与 session。 | 历史解释不能替代当前代码事实。 | 原步骤可中文化压缩。 | 保留目标、git 历史、memory 搜索和不确定性说明。 | 中 |
| `open-code-review` | 调用 OCR 做 AI 代码审查。 | 外部审查工具必须先验证安装、LLM 和输出。 | 参数说明和优先级定义重复。 | 保留前置检查、常用命令、分类、规则和验证。 | 高 |
| `browser-verification` | 用 DevTools MCP 做真实浏览器验证。 | UI 运行时事实只能在浏览器中确认。 | 安装、示例测试计划过长。 | 保留使用时机、安全边界、UI/network/perf 流程和验证清单。 | 高 |

## 后续建议

- 将所有长 skill 控制在“触发 + 流程 + 输出 + 禁止项/验证”的结构内。
- 辅助 Markdown 只承载按需细节，不重复主 skill 的门禁。
- metadata 只放路由所需关键词，避免与正文维护两套长描述。
- 每次新增 skill 时同时写明第一性原理和最小必要步骤，防止默认堆叠流程。
