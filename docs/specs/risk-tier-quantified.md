# 快速/轻量/完整档位判定

状态：Implemented

风险控制以 [执行内核](../rules/governance-core.md) 为准，检查选择以 [测试规则](../rules/test-rules.md) 和项目验证配置为准。本页提供应用示例，不定义第二套审批或验证门禁。

## 判定依据

先确定用户可观察结果、必须保留的行为、授权范围与交付层级，再判断公共契约、安全、数据、外部系统、可逆性和实际影响面。无法界定影响时先补事实或扩大必要验证。

行数、文件数、共享代码比例和预计耗时只用于估算阅读与执行成本，不直接决定风险、测试层级、人工批准或是否创建 worktree。风险档位、quick/standard/deep 成本层、L0–L6 证据层和本地/集成/发布交付范围分别判定。

## 场景

| 场景 | 风险与证据选择 | 完成边界 |
| --- | --- | --- |
| 大批纯文档或机械文案修改 | 可按快速档静态核对，按实际影响做文档检查；不因超过行数或文件数自动运行矩阵 | 文档修改完成 |
| 一行权限或认证逻辑修改 | 完整档，核对授权及调用链，验证允许与拒绝路径、相关契约/集成 | 仅宣称取得证据的行为与环境 |
| 跨模块但可逆的本地逻辑变更 | 按真实耦合选择受影响单元、组件或契约切片；不固定要求独立审查或 deep | 本地实现或已验证集成分别表述 |
| 数据迁移 | 完整档，验证数据语义、幂等、失败恢复及必要回滚 | 未验证生产环境时不宣称生产迁移成功 |

普通 REPL 不能替代正式完成证据；L1 Micro 仅在项目声明且适用时运行。低层通过不能覆盖高层失败。高风险不自动触发 L6；全量矩阵只在明确请求或实际发布、未知影响等必要边界选择。
