# Cognis v0.7 自适应单/多 Agent 编排规格

状态：Implemented

版本说明：`v0.7` 是治理规格修订号，不等同于 `package.json` 的产品版本。本规格继承 v0.6 的 v2 父子任务合同、单一 Markdown 真值、扁平 DAG、父 Agent 单一派发、fan-in 复验和独立 Red Team，并以自适应编排规则替代 v0.6 的多 Agent 选择政策。v0.6 作为历史规格保留，版本关系由 `docs/catalog.json` 记录。

## 目标与决策顺序

每个请求按 `风险分级 → 需求分类 → 编排判定` 处理：风险档位控制安全、验证和审查强度；需求分类识别工作形态；编排判定再决定单 Agent、单 Agent 串行或多 Agent。Agent 数量不是风险等级，完整任务也不必然拆分。

默认使用单 Agent。文档查询、代码定位、只读解释、文案修改、局部样式、单页面调整、单模块功能和小型缺陷修复保持单 Agent。跨层任务若共享契约、文件或边界较多，也由单 Agent 串行执行，可另加独立 Reviewer。

## 多 Agent 准入门禁

复杂可拆任务只有同时满足以下全部条件，才自动启用平台原生多 Agent，无需额外确认：

1. 至少有两个可独立验收并产生明确交付物的工作单元。
2. 每个 child 的输入、输出、项目相对写入范围和依赖可在派发前固定。
3. 同一执行批次的 child 写入范围不重叠；共享边界必须串行。
4. 每个 child 有确定性、可重复验证，父任务有 fan-in 后的集成验证。
5. 平台或 adapter 提供真实子 Agent 能力，且隔离与并行收益高于派发、协调和 fan-in 成本。

任一条件不满足时记录判定依据并保持单 Agent。平台能力不可用时降级为单 Agent，不模拟或虚构多 Agent 执行。用户要求增加 Agent 数量不得绕过准入门禁；新手、标准、专家等交互偏好只改变解释深度和确认频率，不改变风险、安全、验证或编排结论。

## Prompt Cache 上下文边界

上下文继续按稳定前缀、动态后缀和当前请求组织。稳定前缀只包含治理规则、专项规则、profile/工具能力、adapter 能力和规范指纹；child 只接收完成其边界所需的最小、稳定上下文，不继承无关历史。任务切换、规范变更或 adapter 变更会使对应缓存层失效，且不改变现有 `governanceHash` 的语义。

工作区状态、命令输出、时间敏感证据和 child 结果属于动态后缀。父 Agent 在 fan-in 后必须刷新动态上下文、检查实际 diff 并复验集成命令，不得复用合并前状态或 child 自报证据。无法提供 prefix cache 的 adapter 发送完整提示，安全与验证门禁保持不变；敏感数据和提示正文不得写入持久化缓存。

## 执行与停止合同

- 多 Agent 沿用 v2 single/parent/child schema、固定 child 输出、扁平 DAG、父 Agent 单一派发与单一任务 Markdown；不新增 scheduler、消息总线、平台抽象 API 或持久化运行时字段。
- 父 Agent 默认最多同时运行三个 ready child；adapter 只能进一步降低并发上限。同批 child 必须无依赖、无冲突且写入范围不重叠。
- child 不得再委派、创建孙任务、修改任务控制文档或扩大范围。Build 实现角色不得修改或放宽验收条件；合同有误时必须阻塞并交由父 Agent 决策。
- 同一 child 连续三次验证失败、发生范围漂移或需要再拆分时，必须停止并上报父 Agent，不得无限重试。
- Judge 或 Reviewer 必须独立于 Build 实现角色。父 Agent 在 fan-in 后检查实际 diff，并在目标工作区重新运行集成验证；child 自报测试或自审不能替代集成证据。

## 安全、能力与兼容

自动派发仅适用于用户已授权、可逆且不涉及红区的范围。安全分析和核验可以拆分，但外部发布、权限变化、红区、破坏性操作、不可逆动作和未决业务决策仍保留人工门禁。

full profile 可使用平台真实子 Agent 能力；多 Agent 边界与验证由治理和 Runtime 承担，不再依赖流程 Skill。其他 profile 或能力不足的平台按单 Agent 降级并明确报告。CLI 命令面、v2 task schema、治理校验与 adapter 选择行为均保持不变。

## 验收场景

- 普通查询、文档编辑、局部页面调整和单模块修复不派发 child。
- 前端、后端和文档具备独立边界、独立验收与独立验证时，可形成合法执行批次并自动派发。
- 多个工作项共享 schema、文件或未固定接口时，不得并行写入，改用单 Agent 串行执行。
- 显式要求“尽量多用 Agent”不能覆盖门禁；交互偏好不能降低风险、安全和验证要求。
- 连续三次失败或范围漂移会阻塞 child；fan-in 完成后必须产生目标工作区的新鲜集成证据和独立审查结论。
