# API 规则

API 规则用于保护契约稳定性、边界输入和兼容演进。变更接口前必须识别调用方、错误语义、兼容策略和测试覆盖；跨越信任边界的请求、响应、事件、配置和第三方数据必须经过校验。

## 适用边界

- 适用：公开或跨仓 API、被消费的模块边界、事件与消息 schema、配置契约和第三方 API 消费。
- 沿用目标项目已有的接口风格、版本策略和契约工具；本规则只补底线与最低证据，不新建第二套体系。
- 私有内部实现和一次性可逆的局部改动按 coding-rules 处理，不为其引入版本号、幂等键、兼容层或契约测试。

## 规则

- 以项目既有的 spec、schema 或公开契约为唯一真值，同步实现、mock 和文档；不臆造 API、字段、错误码或权限码。
- 变更接口前确认调用方、错误格式、兼容策略和测试覆盖。
- 对请求、响应、事件、配置和第三方结果使用结构化校验，不用猜测替代契约。
- 写操作定义幂等与重试语义，并发写入定义冲突结果；重复投递按去重处理。
- 交付时写清影响范围、验证命令和未覆盖风险。

## 检查清单

- 调用方：列出直接调用方、外部依赖和跨仓影响；存在未知消费方时按兼容窗口保守处理。
- 契约：说明请求、响应、错误格式、状态码、字段默认值与可空性、未知字段与未知枚举值、时间和数值表示，以及兼容策略。
- 权限：确认认证与授权边界、对象级归属校验，以及权限失败时的响应语义。
- 幂等：写操作说明幂等键或自然幂等、重复请求结果、超时与重试边界。
- 校验：对外部输入、第三方返回、mock 数据和配置使用结构化校验，并明确大小、批量和频率上限。
- 测试：覆盖成功、失败、空值、未知字段、权限失败、重复请求和向后兼容，并覆盖消费方一侧。
- 文档：公开接口变化必须同步 Spec、README、schema 或示例。
- 演进：优先新增可选字段和兼容行为；删除、改名、改类型、收紧校验、改枚举语义或新增错误码必须提供迁移和弃用路径，以及可观察的使用量核对方式。
- 错误：同一接口面使用一致且可机读的错误结构，保留关联标识，不泄漏内部实现或敏感数据；下游错误映射为自有错误面。

## 验证证据

- 契约测试或 mapper/service 测试命令和退出码，以及消费方一侧的验证。
- 关键请求/响应样例、schema 校验输出，以及契约 lint 或破坏性变更检测输出。
- 未覆盖调用方、兼容窗口和剩余风险，含第三方超时、重试与降级行为。

## 停止条件

调用方、兼容策略、权限语义、幂等语义或错误格式不清时先查源码、消费方和公开契约，不编造 API、字段或权限码。仍需高影响产品决定或新增授权时按 governance-core 暂停受影响部分，独立工作继续。

本规则定义适用边界与最低证据；按需展开的执行步骤见宿主 Skill 根目录下已安装的 `api-and-interface-design` Skill 入口，两者描述同一契约，修改须同步。
