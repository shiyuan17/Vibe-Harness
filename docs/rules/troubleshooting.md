# 排障规则

本规则定义排障的证据、归因、交付与停止边界；未知根因的定位方法与假设迭代见 systematic-debugging Skill，日志与遥测侧的证据收敛见 log-management。排障必须从可复现证据出发，而不是从猜测出发。

## 规则

- 先固化现场：在重启、清理、回滚或改配置前保存日志、堆栈、dump、配置与版本快照；共享或生产环境优先只读诊断，避免诊断动作破坏唯一证据。
- 先缓解后定根因：在已有授权范围内优先执行可回滚的缓解动作（回滚、开关、隔离、限流）；缓解不得替代根因证据，并记录动作内容和时间点。
- 用差异与二分收敛：确认最后一次已知正常状态，对比正常与异常环境的版本、配置、数据和依赖差异，必要时对变更集二分。
- 每个修复都应对应一个能防止回归的验证；可复现缺陷必须把最小复现固化为自动化回归测试，只有依赖无法自动化的外部环境时才使用人工核对并记录原因。
- 交付时写清影响范围、验证命令和未覆盖风险。

## 检查清单

- 症状：记录实际错误、含时区的绝对时间、精确版本或 commit SHA、运行时与依赖锁定版本、环境、频率和影响范围；确认工作区状态（未归属改动、stash、worktree）与基线一致。
- 最小复现：给出最小命令、步骤、输入或测试，并确认正常与异常环境的版本和配置一致，避免把环境差异当作缺陷。
- 分界：确认基线后的相关变更、最后一次已知正常状态、相关模块、外部依赖和排除项。
- 假设：每次只验证一个主要假设，观察结果要能证伪；优先寻找能推翻当前假设的证据。
- 修复：修复必须对应回归测试、验证命令或人工核对；根因证据必须指向最早错误状态，不能只凭症状消失就判定根因已定位。
- 变更：一次只改变能验证当前假设的最小变量；不要同时升级依赖、重构和修改配置。
- 记录：按时间顺序记录观察、假设、动作与结果，包含绝对时间戳；多人协作时保持单一记录者。
- 归因：复现或验证有效执行且结果不符时才能标记产品或行为失败；工具、权限、网络、超时或环境阻断时标记为验证受阻（degraded），不归因为产品通过或失败。
- 未复现：先缩小结论，记录已排除范围，继续检查静态证据、边界条件和无需额外授权的可证伪假设；不得把“本地未复现”当作问题不存在或自动停止的依据。

## 验证证据

- 失败复现命令和退出码。
- 修复后的通过命令和关键输出。
- 因果证据：不破坏共享环境的前提下，移除修复或注入故障后症状按预期重现，而不是只证明修复后症状消失。
- 验证受阻时的失败阶段、替代证据、未验证行为和剩余风险。
- 未复现、间歇性或环境依赖风险。
- 现场证据（日志、堆栈、dump、trace、截图）写入 `.vibe-harness/artifacts/`，不得包含凭据、原始 Hook 负载、原始 PII 或其他敏感数据。

## 收尾

- 收敛根因与贡献因素，说明为什么没有更早发现，并把防回归验证并入回归套件。
- 记录后续动作与负责人；非重大故障可合并为一段结论。

## Hook 入口错误

- HOOK_INPUT_INVALID_JSON：检查 Hook 配置是否向 stdin 传入一个完整 JSON 对象。
- HOOK_INPUT_TOO_LARGE：缩小宿主传入的事件负载；不要提高 1 MiB 安全限制来绕过诊断。
- HOOK_INPUT_INVALID：核对当前宿主的必填事件字段，不要把原始输入复制到日志或任务记录。
- HOOK_EVENT_MISMATCH：核对 Hook 注册的 lifecycle event 与 expected-event 参数。
- HOOK_PROJECT_CONTEXT_UNAVAILABLE：确认宿主提供的项目目录存在、可访问且指向当前项目。
- HOOK_RUNTIME_ERROR：运行 vibe-harness doctor，先核对 runtimeHooks.activated、enforced 和 coverageLimitations；兼容字段 selfCheck 仍为 degraded 时，保留错误类别与最小复现，不保留原始负载。

doctor 的 Hook 自检只验证包内受审策略引擎在 guarded 策略下拒绝合成越界写请求；它不加载目标项目代码，也不证明宿主已加载或信任 Hook，宿主激活仍按 runtimeHooks.activation.verification 核对。

## 停止条件

只有继续诊断需要产品决策、额外权限或生产访问，修复涉及不可逆行为，或必须扩大授权范围时停止并升级。同一假设连续无进展或时间盒用尽后换路或升级，不重复同一次尝试；缺少日志或无法复现时先报告证据边界，并继续无需额外授权的静态分析和范围收敛。
