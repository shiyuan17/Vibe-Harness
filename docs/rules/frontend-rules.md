# 前端规则

前端规则保护可用性、状态一致性、可访问性、输入安全和真实浏览器行为。样式体系、性能阈值和浏览器矩阵优先遵循目标项目既有契约；任务未触及对应领域时，不因其缺失阻塞局部修复。

## 适用边界

- 布局或交互变更应覆盖受影响的加载、空态、错误、窄屏和长文本状态；纯文案或不改变行为的局部修复只验证受影响内容。
- 项目已有设计令牌、主题、组件状态或品牌体系时沿用，不创建第二套体系；只有任务明确要求建立或迁移设计系统时才补建令牌。
- 项目已有 CSP、Trusted Types、SRI、性能预算、虚拟化阈值或浏览器矩阵时遵循；任务明确涉及对应威胁、资源或性能瓶颈时按实际证据补充。

## 底线规则

- 不得禁用浏览器缩放；不得使用 <code>user-scalable=no</code> 或 <code>maximum-scale=1</code>。
- 移除默认 outline 时必须提供可见焦点反馈，不能用无替代的 <code>outline: none</code>。
- 破坏性操作必须要求确认或提供可恢复的 Undo 安全窗口。
- 导航使用链接语义，操作使用按钮语义；不得用非语义元素替代可交互控件而不提供等价键盘与辅助技术支持。
- 用户输入和其他不可信内容不得直接注入 HTML；<code>postMessage</code> 校验来源，嵌入内容按目标项目威胁模型设置 sandbox 和权限。
- 不得因重复提交、过期异步响应或权限状态错误造成数据损坏、越权操作或不可恢复状态。

## 检查清单

- 状态：只覆盖本次行为实际影响的加载、空态、错误、成功、禁用和长文本状态。
- 可用性：交互控件可发现、可聚焦、可恢复，错误文案能指导下一步。
- 可访问性：使用语义 HTML、合理 heading 层级和可见焦点；正文与控件对比度达标；尊重 <code>prefers-reduced-motion</code>。
- 响应式：布局变更覆盖目标项目支持的窄屏、桌面和内容溢出场景；触摸目标和媒体处理遵循现有设计体系与可访问性要求。
- 浏览器：关键布局和交互用目标项目支持的真实浏览器验证；纯文案或无浏览器影响的变更可以用更窄的证据。
- 安全：防止 XSS；已有 CSP、Trusted Types、SRI、iframe 或跨窗口通信策略时保持兼容，新增策略由明确威胁模型和部署条件驱动。
- 行为：防止重复提交、旧响应覆盖新状态、失败后无恢复入口和权限不足时仍暴露操作。
- 契约：公共视图模型和 transport DTO 边界变化遵循目标项目既有 adapter 或 mapper 契约。
- 性能：发现无界渲染、重复请求或布局抖动时用实际数据决定分页、虚拟化、懒加载或预算；列表项数量本身不构成通用阈值。

## 设计建议

- 已有令牌体系时通过语义令牌引用颜色、字体、间距、圆角和高度，并复用项目已有强调色与主题映射。
- 新建或显著修改交互组件时覆盖其实际支持的默认、悬停、按下、聚焦和禁用状态。
- 动效优先使用 <code>transform</code> 和 <code>opacity</code>，避免无边界的 <code>transition: all</code>；若必须动画布局属性，说明性能与可访问性取舍。
- 不为视觉变化改写无关业务逻辑，不因通用审美偏好覆盖目标项目已接受的品牌选择。

## 验证证据

- 与完成主张匹配的组件或页面测试、项目已配置且适用的 lint/typecheck，以及必要的浏览器检查。
- 布局或交互变更可用截图、步骤记录或状态核对补充证据。
- 记录未覆盖的设备、浏览器或交互风险，不把未执行检查描述为通过。

## 停止条件

只有缺少产品或设计决策会改变结果、需要额外权限或生产操作、会执行不可逆或破坏性行为、或必须扩大授权范围时停止并请求确认。令牌体系或完整浏览器矩阵缺失不阻塞与其无关的局部修复；先缩小范围并报告未覆盖风险。
