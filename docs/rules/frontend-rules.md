# 前端规则

前端规则保护可用性、状态一致性、可访问性、输入安全和真实浏览器行为。本规则定义门槛与验收口径，实现工艺由领域能力按需补充；样式体系、性能阈值和浏览器矩阵优先遵循目标项目既有契约，可访问性以 WCAG 2.2 AA 为基线，项目有更严标准或法律基线时从高。任务未触及对应领域时，不因其缺失阻塞局部修复。

## 适用边界

- 布局或交互变更应覆盖受影响的加载、空态、错误、窄屏和长文本状态；纯文案、按钮文本或不改变交互与数据流的局部微小修复属于快速档，仅核对受影响文本与语法，严禁为此类修改补充或运行端到端 (E2E) 自动化测试。
- 项目已有设计令牌、主题、组件状态或品牌体系时沿用，不创建第二套体系；只有任务明确要求建立或迁移设计系统时才补建令牌。
- 项目已有 CSP、Trusted Types、SRI、性能预算、虚拟化阈值或浏览器矩阵时遵循；任务明确涉及对应威胁、资源或性能瓶颈时按实际证据补充。
- 门槛按领域触发：未触及可访问性、本地化、媒体或性能时不为补齐清单扩大范围，只记录未覆盖风险。

## 底线规则

- 文字与界面可缩放：不得使用 `user-scalable=no` 或 `maximum-scale=1` 禁用浏览器缩放；200% 缩放与 320 CSS px 宽视口下不丢失内容或功能，也不得为此强制二维滚动。
- 键盘可达、焦点可见且不被遮挡：不移除无替代的 `outline`，焦点指示器与相邻背景对比度达标；固定头部、吸底栏与浮层不得遮挡当前焦点元素。
- 模态与视图切换管理焦点：对话框或抽屉打开时焦点限制在其内部，关闭后归还触发元素；视图或路由切换后焦点与文档标题反映新上下文。
- 指针目标足够大且可替代：交互目标不小于 24×24 CSS px，移动端按目标项目设计体系（无体系时取 44×44）；拖拽或滑动类操作必须提供单击或键盘等价路径。
- 破坏性操作必须要求确认或提供可恢复的 Undo 安全窗口。
- 导航使用链接语义，操作使用按钮语义；不得用非语义元素替代可交互控件而不提供等价键盘与辅助技术支持；状态与错误变化可被辅助技术感知，错误与对应字段程序化关联。
- 表单输入可识别、可复用且不丢失：字段有持久标签与 `autocomplete`/`name` 语义；不得阻止粘贴、密码管理器或一次性验证码自动填充；同一流程不重复索取已提供的信息；提交失败保留用户输入。
- 不可信内容不得直接注入 HTML、属性、URL、CSS 或 SVG；必须渲染富文本时经白名单净化；`postMessage` 在接收侧校验来源与负载、在发送侧限定目标来源，嵌入内容按目标项目威胁模型设置 sandbox 和权限。
- 前端不承担授权与密钥保管：前端权限状态只影响呈现，鉴权以服务端为准；密钥、令牌与敏感数据不进入客户端包或可被脚本读取的持久存储。
- 不得因重复提交、过期异步响应或权限状态错误造成数据损坏、越权操作或不可恢复状态；写操作使用幂等键，过期响应不得覆盖新状态，乐观更新失败必须回滚或提供 Undo，缓存按身份隔离，重试有上限与退避。

## 检查清单

- 状态：只覆盖本次行为实际影响的加载、空态、错误、成功、禁用和长文本状态；错误与失败路径提供恢复入口。
- 可用性：交互控件可发现、可聚焦、可恢复，错误文案能指导下一步。
- 可访问性：使用语义 HTML、合理 heading 层级和可见焦点；正文与控件对比度达标（正文 4.5:1、大字 3:1，控件、状态与焦点指示器 3:1）；不只用颜色传达信息；尊重 `prefers-reduced-motion`；高对比与强制色模式下边界与焦点不丢失。
- 响应式：布局变更覆盖目标项目支持的窄屏、桌面和内容溢出场景；长字符串与用户内容有明确溢出策略；软键盘弹出不遮挡当前输入；触摸目标和媒体处理遵循现有设计体系与可访问性要求。
- 本地化：涉及多语言或 RTL 时覆盖语言与书写方向声明、逻辑属性、文本扩展和 locale 格式化。
- 媒体：涉及音视频时覆盖字幕、自动播放控制、可暂停能力和闪烁约束。
- 浏览器：关键布局和交互用目标项目支持的真实浏览器验证，无矩阵时至少覆盖主流 Chromium 与移动端 WebKit 的窄屏视口；纯文案或无浏览器影响的变更可以用更窄的证据。
- 安全：防止 XSS；已有 CSP、Trusted Types、SRI、iframe 或跨窗口通信策略时保持兼容，新增策略由明确威胁模型和部署条件驱动；第三方脚本按最小来源与完整性校验引入。
- 行为：防止重复提交、旧响应覆盖新状态、失败后无恢复入口和权限不足时仍暴露操作。
- 契约：公共视图模型和 transport DTO 边界变化遵循目标项目既有 adapter 或 mapper 契约。
- 性能：发现无界渲染、重复请求或布局抖动时用实际数据决定分页、虚拟化、懒加载或预算；优先现场 p75 或真实浏览器性能轨道数据，Core Web Vitals 作为通用参照而非硬门禁；列表项数量本身不构成通用阈值。

## 设计建议

- 已有令牌体系时通过语义令牌引用颜色、字体、间距、圆角和高度，并复用项目已有强调色与主题映射；暗色模式用 `color-scheme` 与令牌映射，不用散落覆盖。
- 新建或显著修改交互组件时覆盖其实际支持的默认、悬停、按下、聚焦和禁用状态。
- 动效优先使用 `transform` 和 `opacity`，避免无边界的 `transition: all`；自动播放或循环动效必须可暂停；若必须动画布局属性，说明性能与可访问性取舍。
- 不为视觉变化改写无关业务逻辑，不因通用审美偏好覆盖目标项目已接受的品牌选择。

## 验证证据

- 与完成主张匹配的组件或页面测试、项目已配置且适用的 lint/typecheck，以及必要的浏览器检查。
- 可访问性主张以可访问性树、仅键盘走查或人工核对矩阵为证据；自动化扫描结果只作辅证，不替代人工判定。
- 性能主张以现场 p75 或真实浏览器性能轨道数据为证据；没有现场数据时说明采集缺口，不用单次本地采样替代。
- 布局或交互变更可用截图、步骤记录或状态核对补充证据。
- 记录未覆盖的设备、浏览器或交互风险，不把未执行检查描述为通过。

## 停止条件

产品与设计的高影响分歧、权限、生产、不可逆或破坏性操作按 governance-core 核对当前意图和覆盖授权；仅暂停缺少必要决定或授权的部分，已有批准不重复询问。令牌体系或完整浏览器矩阵缺失不阻塞与其无关的局部修复；先缩小范围并报告未覆盖风险。
