# 测试规则

## Fast Path 卡片

- **默认路径**：按改动行为风险选最小充分检查 → 记录实际命令、退出码与结果 → 完成主张只覆盖本轮验证到的范围。
- **按风险选择**：普通对话与纯文案只做受影响文件的静态检查；局部行为用受影响范围的聚焦测试；共享行为、UI、数据迁移、安全与发布才升级到集成、浏览器或端到端；全量测试不是默认验证。
- **受阻与回退**：工具缺失、权限、网络、超时或环境异常导致检查未有效执行时记为 blocked（degraded），不推断产品通过或失败，也不通过降低断言、删除断言或无理由跳过相关测试绕过。
- **收据复用**：同一指纹、同一命令集合且此后无实质写入才复用已 passed 的收据；有实质写入必须重跑。
- **继续读全文的信号**：成本分层门禁、E2E 准入、深度异步收据、长命令超时、flaky 隔离或测试与 Eval 边界。

以下为完整规则，仅当任务超出卡片或命中升级触发时继续读取。

测试范围与完成主张匹配；不因任务档位自动运行固定矩阵。验证、证据强度、验收状态和交付主张由 governance-core 统一定义，本规则只说明测试类型、专项基线和选择差异。

| 行为风险类别 | 建议验证 |
| --- | --- |
| 普通对话 / 只读诊断 | 事实核对、静态检查或无需命令 |
| 纯文案 / 按钮与静态标签 | 仅需受影响文件基础静态检查（diff/lint），不新增测试用例，不跑 E2E/浏览器或全量测试 |
| 局部行为 | 受影响范围的聚焦测试和项目已配置且适用的 lint/typecheck |
| 共享行为、公共契约 | 调用方回归与集成检查 |
| UI | 组件测试和真实浏览器关键状态；可访问性与浏览器矩阵基线见 frontend-rules |
| 数据、迁移与回滚 | 迁移、幂等、边界与恢复路径验证；数据基线与证据见 db-rules |
| 安全、发布 | 正向/负向路径、边界、回滚与必要的环境验证；适用时含故障注入 |

上表按行为风险补充选择维度，不替代项目常驻指令文件中声明的「验证选择」：路径到命令的规范矩阵以项目已声明的为准，并先用项目提供的聚焦验证入口生成本轮建议计划，再按上表补齐行为风险需要的检查。本规则只约束 Agent 自主验证范围，不覆盖目标项目自身配置的 CI 门禁。

全量测试不是默认验证；仅在用户明确要求、CI/发布要求、影响面无法缩小或项目自身配置为门禁时运行。`test` 或等价的完整聚合入口（一次跑完所有层）不是普通变更的默认命令；分层运行：开发中与提交前保持快速反馈，合并前运行项目声明的必跑集，关键 PR、夜间与发布边界才运行深度层。独立 Review 不自动派发；浏览器验证和 Eval 仅在变更或完成主张需要时选择，不因记录、角色或任务档位自动触发。

对于按钮文本、静态标签、提示文案等微小非行为变更，不新增或补充单元/组件/E2E 测试用例，也无需触发端到端运行；既有测试若断言了旧文案，如实报告而不把该套件当作本规则的前置阻塞门禁，但目标项目自身的 CI 门禁仍然有效。

记录实际命令、退出码和关键结果，验收状态按 governance-core 的 passed、failed、blocked、unverified 归类：检查有效执行且断言不符时记为 failed；工具缺失、权限不足、网络失败、超时或环境异常导致检查未有效执行时记为 blocked，即验证受阻（degraded），不得推断产品通过或失败。失败不得通过降低断言、删除断言或无理由跳过相关测试绕过；验证受阻时缩小完成主张，并记录失败阶段、替代证据、未验证行为和剩余风险。

验证记录保留必要判据、实际命令结果和存在的未验证项、风险；简单任务使用证据摘要，不强制验收矩阵或完整输出。覆盖率是诊断信号不是目标，不得为凑覆盖率数字编写缺乏断言价值的测试；需要更强的断言有效性信号时，用增量覆盖率、关键模块的变异测试（如 Stryker、PIT）或负控（先让已知坏样本失败）确认检查本身有效。

## 长命令与收据复用

单条检查的时长上限是 Agent 墙钟预算，与测试运行器的单用例超时是两个口径，独立使用，不得混写：

| 口径 | 含义 | 超限处理 |
| --- | --- | --- |
| Agent 墙钟预算 | Agent 等待单条「项目声明的检查命令」完成的时长预算；项目未声明上限时参考 10 分钟 | 超过上限按 blocked 处理：停止等待，记录已执行时长与未完成部分 |
| 运行器单用例超时 | 测试运行器对单个用例配置的失败兜底超时 | 按项目测试配置处理，不由墙钟预算替代或改写 |

- 端到端失败后先用「单 spec」或「--grep 聚焦」定位失败原因，禁止原样整轮重跑。
- 端到端启动前做「端口与残留进程自检」：核对项目声明分配的端口空闲、无残留服务或浏览器进程；发现占用先查端口归属，确认归属后再终止，无法确认时报告。
- 收据复用前提是「同一指纹、同一命令集合、此后无实质写入」：前提满足且该检查已 passed 时，复用原收据，不重复执行。指纹是受检对象状态（如工作树内容）的稳定摘要，命令集合是收据实际执行的检查命令清单。
- 前提不满足时不得复用：指纹或命令集合变化按本轮检查重新执行；出现实质写入即失去复用资格。复用边界与「最后一次实质修改后的状态重跑同一检查」同向：无实质写入可复用，有实质写入必须重跑。

## 测试金字塔与成本分层

测试规模按金字塔分布：单元测试是主体，组件与集成测试补充被证明的必要边界，端到端只保留核心业务主链路和关键风险流程。低层能证明的行为不写高层用例；用例数量不是目标，按风险选择最小能证明该行为的层。

| 成本层 | 覆盖 | 运行时机 | 阻塞范围 |
| --- | --- | --- | --- |
| 快速 | 静态检查与单元层；组件层默认计入快速层，重型组件套件可在项目配置中显式归入中等层 | 开发过程中同步执行，随改动反复运行 | 失败阻塞当前实施单元 |
| 中等 | 集成、契约与 API 边界（含按项目配置移入的组件层） | 实施单元边界、提交前或合并前执行 | 失败阻塞合并或完成声明 |
| 深度 | 端到端、全量矩阵、性能与 Eval 契约重放 | 异步、夜间、关键 PR 或发布边界执行 | 失败阻塞集成、发布或依赖该证据的完成声明 |

同步/异步边界按上表固定：快速层失败就地修复后再继续实施，不得带着失败继续扩展改动；中等层失败阻塞合并与完成声明；深度层允许延迟执行，但未取得该层证据前不得声称集成、发布或整体完成。深度层由项目自身的 CI、独立工作区或显式分层命令承载，Agent 不为等待深度结果阻塞主实施流程，也不假设存在常驻后台服务。

可执行形态：`vibe-harness verify` 默认只执行快速层，中等层与深度层必须显式升级（`--tier standard|deep`，或 `--full` 的完整矩阵）；快速层通过时收据标注部分范围并列出被延迟的检查与下一层入口，不会被当作完整验证。验证有两个可执行入口——`vibe-harness` CLI 与安装到目标项目的 `run.mjs verify`（`.agents/runtime/commands/run.mjs`）——层命令同源于项目配置的 `validationCommands`，收据以 `engine` 字段标注产出具名（`vibe-harness-cli` / `vibe-harness-runtime`），引用收据时先核对 `engine`。成本层的触发条件见 governance-core 的「成本与升级」。

### E2E 准入

只有真实入口驱动的完整旅程才进入端到端层：入口可以是 CLI、API 或浏览器，但必须走项目的真实启动路径。参数校验、配置解析、单个提示文案、可注入组件行为下沉到单元、组件或集成层。每条端到端用例必须说明低层为何无法证明该行为；默认每个关键旅程保留 1–3 条，总量软预算不超过活跃用例的 10%。普通检查只对超出预算告警，发布 CI 可选择严格模式；数量预算是规则级软约束，硬门禁由目标项目自身的 CI 实现。

### 深度异步收据与失败回流

- 异步深度收据的调度状态是 queued、running、passed、failed、blocked、stale，只说明排期进度；最终验收仍只用 passed、failed、blocked、unverified 四种状态，调度状态不得当作验收结论。
- 新实质写入使未完成的深度任务和旧深度收据 stale：该收据不再覆盖当前状态，需按新指纹重新执行后才能引用。
- 确定性失败先做最小复现再修复，不靠重跑或放宽断言绕过；瞬时基础设施失败允许有界重试，最多三次并记录重试次数。
- flaky 用例只做一次诊断重跑；仍不稳定即隔离，隔离项必须绑定技术债 ID、owner 和关闭条件，不以重跑掩盖。

## 测试分层

测试按层归属，层级必须可机械核对：新项目默认 `tests/<layer>/` 目录，既有项目沿用自身结构并在项目配置或测试清单中声明层级映射。每层只声明该层能证明的行为，低层通过不得替代高层结论。

| 层 | 覆盖面 | 运行边界 |
| --- | --- | --- |
| 单元 | 单函数或模块逻辑 | 每次受影响改动，毫秒级 |
| 组件 | 子系统内组合、组件渲染与交互，不启真实浏览器与后端 | 每次受影响改动，秒级 |
| 集成 | 真实文件系统、子进程、服务进程与测试数据库，不启浏览器 | 受影响子集，提交前或隔离工作区 |
| 端到端关键路径 | 真实入口与真实服务上的少量主流程 | 关键 PR、夜间或发布边界，默认异步 |
| 全量矩阵 | 浏览器、宿主、平台矩阵与权限、数据组合 | 发布边界或夜间 |

端到端层按准入规则收敛（见「测试金字塔与成本分层」的 E2E 准入）：它只证明真实入口的完整旅程，低层已能覆盖的行为留在低层。

- 跳层必须写明理由：低层已能证明的行为不重复上高层，高层失败不得用低层通过掩盖；纯文案、按钮文本与静态标签改动不触发端到端层。
- 每层的命令入口、并发与超时由项目声明；端口、数据库与容器资源从该层声明的分配环境读取，不硬编码，同机多工作区并行时按分配结果隔离。
- 用例退役、合并或跨层移动必须同步更新归属声明，不留只在某一层登记的影子用例。

### 用例约定

- 一用例一个失败原因：同一用例内不混合多个独立行为，失败信息能直接指出被破坏的行为。
- 命名与描述描述行为而不是实现细节，包含可核对的前置与预期；用例改动只跟随行为变化，重构不要求同步改用例名。
- 表驱动用例必须参数化命名，使每个失败行可单独定位，不用循环拼接无法定位的名称；归属清单按声明保留一条参数化条目，运行时展开的实例由该条目的占位符匹配，不为每行重复登记。
- 新增或重写的用例描述使用项目 `language` 声明的语言（默认中文）；既有存量描述可随相关改动逐步收敛。
- 临时资源、临时目录与子进程在用例结束（含失败）时清理；不使用无理由的只运行或跳过标记。
- 同一行为不在同层重复覆盖；用例隔离、退役、重命名或跨层移动必须回写项目提供的归属清单或用例台账。
- 台账附带的静态覆盖映射（测试文件 → 相对 import 可达的源文件）是下界语义：未列入代表“归属未知”，不等于“不受影响”；文件级聚焦只在该映射完整归因全部变更源时生效，任一源未被覆盖即回退整层。

## 测试类型

按改动类型选择测试，不为凑数运行无关测试；下表是选择清单，非强制全覆盖矩阵。

| 类型 | 何时使用 | 关键属性 |
| --- | --- | --- |
| 静态（lint/typecheck） | 项目已配置且对本次文件或语言适用时 | 捕获笔误与类型错误，不验证业务逻辑 |
| 单元 | 单函数或模块逻辑 | 隔离、快、确定性 |
| 集成 | 多单元协作、公共契约、安装器与适配器 | 验证真实协作边界 |
| 回归 | 已稳定通过的关键行为防回退 | 只证明不回退，不作为能力提升证据 |
| 端到端 / 浏览器 | UI 关键状态与真实用户路径 | 慢且贵，少量覆盖 |
| 可访问性 | 交互、语义或内容变更 | 以 WCAG 2.2 AA 为基线，自动化检查加关键路径人工核对 |
| 性能 / 负载 | 延迟、吞吐或资源有明确主张时 | 用代表性数据，阈值来自项目契约，不用单次本地采样替代 |
| 兼容性 | 项目声明多浏览器、多端或多版本支持 | 按支持矩阵取样，不假设单一环境代表全部 |
| 韧性 / 故障注入 | 依赖失败、超时、部分失败与恢复路径 | 验证降级、重试边界与恢复，不只看成功路径 |
| 属性 | 可表述为不变性质的逻辑 | 随机输入验证不变量并缩小反例 |
| 模糊 | 解析器、编解码与不受信输入边界 | 用畸形输入发现崩溃或异常行为 |
| 契约 | 多服务或 API 边界 | 消费方驱动，防止 spec drift |
| 快照 / golden | 复杂输出回归、遗留代码特征化 | 审批 baseline；更新须单独审查显式确认，非确定性输出禁用 |
| 对抗式 / 负向 | 安全、数据、发布、Agent 安全边界 | 验证禁止行为不发生 |
| Eval（offline） | Agent 规则、Skill、模板、adapter、Hook | 确定性 replay，reference 比对 |
| Eval（online） | Agent 能力上限和可靠性 | 多轮 pass@k、pass^k 和 judge 对齐 |

阈值与专项基线由领域规则持有：可访问性、浏览器矩阵与性能证据见 frontend-rules，数据画像、迁移与恢复证据见 db-rules，安全边界与对抗式场景见 security-and-hardening；本表只列类型，不重复其基线。

Agent 测试终态优先于固定过程：合法替代路径不应判为失败。工具调用的选择、参数和轨迹可作为独立被测对象，不只验证最终输出。关键修改的测试范围应覆盖关系链分析识别的受影响消费方；共享行为或公共契约变更至少包含一条调用方回归断言。

## 工程约定

下述为运行器无关的行为契约；具体运行器、脚本入口与超时值属于项目事实，以项目自己的贡献指南和测试配置为准。

- 使用项目语言惯用测试运行器和既有脚本入口，不为符合本规则引入新运行器。
- 优先隔离共享状态并允许并行；只有共享临时状态、端口、数据库或其他资源无法隔离时才串行运行相关集成测试。
- 测试数据用合成或最小化数据；生产 PII、凭据和真实用户数据不进入 fixture、快照或测试日志，fixture 版本化并固定种子。
- 保持确定性：固定时钟、随机种子、时区和 locale；不依赖测试顺序或真实网络，等待外部条件用轮询，不用固定 sleep。
- 使用语言惯用断言；基准路径相对项目解析，不硬编码机器绝对路径。
- 临时资源在测试结束时清理，断言失败也执行 cleanup。
- 优先依赖注入式替身；需要自动还原时使用运行器内置 mock 机制。
- 不提交无意跳过测试的残留；合法条件跳过必须显式说明环境条件。
- 缺陷修复先写暴露该缺陷的复现测试，再实施修复。
- flaky 测试须隔离并限期修复，不以重跑掩盖；隔离项必须绑定可核对的技术债 ID、owner 和关闭条件，重试只允许有界且必须报告。
- 测试断言行为而非实现细节，重构不应要求同步修改测试；替身只接既有依赖边界，不在产品实现中引入仅测试使用的辅助路径。
- 项目可设置与环境和历史耗时匹配的失败兜底超时。单元和 Eval 约 30 秒、集成约 120 秒仅是 Vibe-Harness 参考值，不是目标项目通用门禁。

### 参考实现边界

本节只声明可移植的参考实现边界：脚本入口按测试层级分类，失败兜底超时按环境与历史耗时设置。具体运行器、脚本名与超时值属于项目事实，不构成对目标项目运行器、依赖或超时的要求。

## 对抗式与负向测试

安全、数据、发布改动应根据风险包含负向断言；Agent 安全边界改动应覆盖对抗式场景。负向断言验证禁止行为不发生，与正向断言互补。

对抗式 case 属于 Eval 范畴：用 kind: adversarial 声明，并用 forbidden event、output fragment 或 artifact 等 oracle 验证禁止行为。场景可覆盖指令注入、敏感信息泄露、越权代理、资源耗尽、不安全输出和供应链边界。

工具失败、网络失败或 judge 不可用时按 fail-closed 转 blocked，即验证受阻（degraded）；degraded attempt 必须保留，不能只报告成功样本，判定细节见 eval-driven-development。

## 测试与 Eval 边界

确定性代码走普通产品测试；Agent 规则、Skill、模板、adapter 和 Hook 的非确定性行为走 Eval。

- eval:replay 用契约重放（contract-replay）做确定性回归比对，不执行当前 Agent 规则、Skill 或 Hook。
- Skill、规则、Hook 或配置的行为约束由对应的审计与运行时测试验证；安全边界变更必须让负向场景保持拒绝，不能用删除断言替代行为验证。
- LLM-as-judge 仅用于 online，判定与 degraded 处理见 eval-driven-development。
- reference 更新必须单独审查并显式确认，不得为让变更通过而自动提升。

测试与 Eval 的执行步骤、oracle 类型和 case kind 见 docs/rules/eval-driven-development.md。
