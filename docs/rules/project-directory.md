# 项目目录规则

项目目录规则记录所有权和依赖方向，让 Agent 能定位正确变更边界，而不是临时发明新结构。

## 适用边界

- 适用：新增、移动或删除目录与模块，判断代码归属，改动跨模块、跨仓或跨服务边界，判断是否需要正式 ADR。
- 不适用：单文件可逆改动、纯文案、只调整测试期望或既有实现细节；这些按 coding-rules 处理，不触发目录与 ADR 判定。
- 沿用目标项目已有的目录、命名和分层约定；本规则只补判断边界与最低证据，不新建第二套结构。

## 发现顺序

1. 读取仓库入口指令；存在当前状态和架构文档时一并读取。
2. 按目标项目生态检查包管理清单、构建入口、模块或可见性声明和 CI 配置，确认模块索引与所有权来源。
3. 需要结构化定位时按 codebase-memory-mcp 规则确认索引状态；纯文本、配置和日志使用 `rg` 与直接文件阅读。
4. 编辑前确认与变更范围对应的测试和验证命令。

## 放置规则

- 领域行为放在拥有对应状态和接口的领域内。
- 共享目录只放已被多个消费者验证可复用的能力，不作为临时堆放区。
- Adapter 只负责外部与内部契约转换，不拥有业务规则。
- 生成物、vendored、构建、缓存、证据和临时目录都不是源码所有权位置，也不作为持久交付物。
- 新增顶层目录必须有架构理由、owner 和依赖方向说明。
- 依赖方向优先用项目已有边界检查验证（依赖图规则、架构测试、构建可见性）；没有工具时按 import 方向与目录归属人工核对，并在交付中说明未覆盖路径。
- 跨领域访问走已声明的公共入口，不深入引用其他领域的实现细节。

## 文档归属

- 文档先找到单一来源和既有格式，避免创建第二套真值；目录级约定写在作用范围覆盖该目录的目录级指令文件，而不是堆进全局规则。
- 面向读者记录当前事实、操作步骤和可验证命令；临时实现流水账不进入耐久文档。

## 架构决策（ADR）

- ADR 遵循目标项目既有制度；没有既有制度时，不为普通修复、局部重命名、可逆实现选择或短期实验新建 ADR 体系。
- 只有长期有效、高影响且难以逆转的架构、公共契约、安全、可靠性、关键依赖或迁移决策才需要正式 ADR；以影响持续时间、消费方范围、迁移成本和回滚难度判断，不以文件数量或是否跨模块边界判断。
- 决策包含问题与背景、决策驱动、备选与取舍理由、结果、后果、确认方式和复核触发条件；ADR 是决策记录而不是设计文档，细节外链。
- accepted 和 rejected 的 ADR 不直接改写；决策变化时新建记录，并用 supersedes / supersededBy 双向关联。
- 项目已建立 ADR 制度时，以其 ADR 索引作为触发清单与流程来源、以其 ADR 模板与 schema 作为字段真值；本规则不维护第二份阈值或字段清单。

| 位置 | 职责 | 不承担 |
| --- | --- | --- |
| 项目正式 ADR 目录 | 正式 ADR 正文、状态流转与复核触发 | 摘要索引与运行态恢复 |
| `docs/memory/DECISIONS.md` | ADR 的 ID、标题、状态、摘要和链接 | 复制 ADR 正文 |
| 本地记忆文件（默认 `.agents/memory/decisions.md`，路径由 `memory.path` 配置） | 跨会话恢复所需的简短本地决策 | 替代正式 ADR |

## 跨边界变更

变更跨模块、package、仓库或服务时，先按可解析的所有权来源确认 owner（CODEOWNERS、模块 manifest、服务目录或文档索引；缺失时在同一变更中补声明），列出每个 owner 和接口，识别兼容与回滚策略，并验证两侧。跨仓执行步骤见 runtime-cross-repo-rollout Skill，契约细节按 api-rules 处理，本规则不重复定义。所有权仍不清晰时停在澄清阶段，不把逻辑散落到多层。

## 完整项目分析

仅在用户明确要求完整项目分析，或跨模块、跨服务、公共契约的影响范围无法缩小时，补充以下内容：

- 技术栈：语言、框架、构建工具和核心依赖版本。
- 目录结构：核心目录职责和关键配置。
- 业务流：入口、处理层级和输出。
- 数据流：来源、处理节点和存储或展示位置。
- 模块依赖：关键耦合和依赖链。

小型 Bug、单文件修改和简单问答不展开该清单。

## 完成标准

- 新增和修改文件都位于声明的所有权边界内，import 遵循已声明的依赖方向。
- 新增顶层目录的 owner 与依赖方向已写进仓库，而不是只存在于本轮对话。
- 测试能证明受影响消费者；无法证明时缩小范围或标记未覆盖路径，不据此声称完成。
- 生成物、缓存和临时证据未混入源码或提交。

以上判据叠加在 governance-core 的完成与验收契约之上，不替代其中的证据标签与授权边界。
