# 审查报告规则

审查报告是缺陷审查、字段口径核对、一致性巡检等只读评审产出的交付物契约：定义 finding 标识、严重度判据、必填字段、结论派生与整改状态源，使不同评审者的报告可对照、可复核、可移交整改。本规则只约束报告形态与证据口径，不新增评审流程或完成门禁；证据标签沿用 governance-core 的定义，不另立口径。

## 适用边界

- 产出带问题清单的书面审查报告时使用本契约；即时问答式的评审结论、评审批注与讨论记录不强制套用。
- 审查对象、基线与检索方法由报告自身声明；报告外壳与排版随项目模板，字段、判据与派生口径以本规则为唯一来源。
- 只读缺陷审查的 Skill 路由遵循 `agent-skill-routing.md`，路由判定与本契约互不替代。
- 本契约不构成流程门或完成门禁：不以产出报告或报告定稿作为修复、验证或交付的前置条件，完成判定遵循 `governance-core.md`。

## Finding 标识

- ID 形如 `<DOMAIN>-F<nn>`：`<DOMAIN>` 为域前缀，`F` 为 finding 固定标记，`<nn>` 为两位十进制序号，示例 `API-F03`。
- 域前缀使用大写拉丁字母缩写，由报告声明并对应本次审查的业务域或模块组；同一整改范围内域前缀含义保持稳定，不混用、不改义。
- 序号在报告内从 `01` 起顺序分配，不跳号；补录时延续现有最大序号，不复用已删除条目的 ID。
- ID 只标识发现本身，不编码严重度或处置状态；跨报告、整改沟通与修复说明引用同一 finding 时原样传递 ID，不改写、不缩写、不重新编号。

## 严重度判据

| 级别 | 判据 |
| --- | --- |
| P1 | 会写错数据或绕过控制：按当前实现执行会产出、变更或暴露错误数据，或使权限、校验、审计等控制面被绕过 |
| P2 | 口径、关联或控件明确错误：字段口径、数据关联或界面控件与契约或声明明确不符，错误可判定且会传导到结果 |
| P3 | 标记与一致性：命名、标记、文档或跨处引用不一致，不直接产出错误结果，但会误导使用方或后续维护 |

- 一条 finding 只标一个级别；同时命中多级判据时取最高级别。
- 级别依据证据锚点可核实的后果判定，不依据推测影响；无法核实的部分写入边界字段，不以拔高或压低级别代替核实。
- 级别描述发现本身的风险，不随处置进度变化；处置进度由整改台账记录。

## 报告必填字段

| 字段 | 含义 |
| --- | --- |
| 现象 | 客观描述偏差表现：对象、触发条件、实际结果与期望结果；不夹带修复方案 |
| 证据锚点 | 可独立复核的定位：文件与位置、标识符、契约条目、请求/响应或查询与参数；敏感数据按 governance-core 的硬边界脱敏，保留最小可复核上下文 |
| 影响 | 按严重度判据说明对数据、控制或使用方的后果，区分实证后果与推断后果 |
| 建议 | 最小可逆的修正方向：改哪里、向什么口径对齐；不替实施者做未经验证的设计决定 |
| 验证状态 | 该发现的核实程度与证据标签，取值见「证据标注」 |
| 边界 | 该 finding 覆盖与未覆盖的范围、静态结论、未验证假设与影响判定的限制条件 |

- 六个字段全部必填；表格或条目可以合并展示，缺失任一字段内容的条目不构成有效 finding。
- 证据锚点必须指向报告读者可独立复核的来源；只描述印象或转述他人结论不满足该字段。

## 结论派生

- 结论总览中的各级别计数与总数由 findings 表逐行派生，不手写、不事后改数；findings 表增删条目或调整级别后必须重新派生。
- 叙述性总结引用的数字与派生结果必须一致；不一致时以 findings 表为准并修正叙述。
- 派生只做计数与占比类汇总，不产生 findings 表之外的新结论；超出计数的判断写成普通叙述并给出依据。

## 整改状态源

- finding 的处置状态以同一份整改台账为唯一状态源；报告、评审沟通和后续会话不各自维护第二份状态。
- 台账以 finding ID 为键，记录处置状态与对应证据指针；状态词汇沿用项目已有跟踪工具的枚举，项目未提供时在台账头部声明并保持稳定，不在中途改义。
- 状态变更写入台账；报告定稿后不回写处置状态，重读报告不能替代读台账，重发或引用报告不改写原 ID。
- 报告中的验证状态与台账中的处置状态是两个口径：前者描述发现被核实的程度，后者描述整改进度，不得互相顶替。

## 证据标注

- 验证状态使用 governance-core「交付与证据标签」的四类人读标签：已确认事实、静态结论、待验证假设、验证受阻；口径以 `governance-core.md` 为准，本规则不新增枚举或同义改写。
- 静态结论必须显式标注：由代码、配置或公开契约推导、未证明运行时行为的发现不得写成已确认事实。
- 未验证边界必须显式列出：未覆盖路径、未能核对的关联、受工具权限数据或环境限制未有效执行的检查，逐条落在边界字段或未验证边界清单，不静默省略。
- 验证受阻的 finding 只记录受阻原因与具体缺口，不得据此推断审查对象通过或失败。
