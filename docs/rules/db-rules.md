# DB 规则

DB 规则用于保护数据完整性、迁移安全、兼容性和回滚能力。出现 schema DDL、数据回填或数据修复、约束变更、事务边界或备份恢复信号时适用；迁移前必须确认数据画像、幂等性、锁影响、事务边界和恢复策略。数据画像指行数、基数、分布、空值率、重复率、历史异常和规模。

本规则只约束数据库 schema 与数据变更本身；发布编排、发布期监控与停止阈值见 release-rules，测试矩阵见 test-rules。

## 规则

- 所有 schema 和数据变更都走版本化迁移：唯一入口、可追溯顺序，已应用的迁移不再修改；不在生产手工执行未版本化 DDL。
- 破坏性变更分段执行：先扩展（新增可空列、新表或新结构）并保持新旧读写兼容，再回填并校验，然后切换读写路径，最后收缩；删除、改名和收窄类型必须晚于代码切换。
- 不假设破坏性变更存在 down 脚本：可逆 DDL 记录降级脚本，不可逆变更声明前滚路径与恢复能力，并按恢复演练证据交付。
- 迁移前确认数据画像、幂等性、锁影响和备份策略。
- 大表变更优先使用并发索引、在线 DDL 或影子表方案，保留节流与中止开关，不以长时间持有排他锁的方式执行。
- 回填与数据修复分批限速、可中断续跑且幂等，与 schema 迁移和代码发布解耦。
- 读写路径要覆盖空值、重复、并发和权限失败；唯一性冲突由约束和幂等写入处理，不依赖先查后插。
- 新增或修改的查询必须给出索引与执行计划依据，不引入 N+1 或无界扫描。
- 变更使用参数化查询和最小权限账号；生产数据不得直接进入本地或测试环境。
- 交付时写清影响范围、验证命令和未覆盖风险。

## 检查清单

- 数据画像：确认现有数据、空值、重复、历史异常和规模。
- 迁移：说明幂等性、锁影响、运行顺序、降级行为和回滚路径，并标注变更处于扩展还是收缩阶段。
- 锁：说明锁级别、锁等待与超时、是否需要并发索引或在线 DDL、复制延迟影响和失败残留的清理方式。
- 回填：说明批次大小与限速、可续跑标记、与代码切换的先后顺序。
- 读写：覆盖并发、权限失败、部分失败和事务边界。
- 并发：唯一性由数据库约束保证；条件更新或版本列防止丢失更新；死锁与序列化失败使用有界重试。
- 查询：关键查询给出索引依据与执行计划结论，避免 N+1 和无界扫描。
- 观测：迁移与回填期间记录错误率、延迟、复制延迟和中止阈值。
- 备份：高风险数据变更必须记录备份或恢复策略，并给出恢复演练证据（RPO/RTO 与恢复耗时）。
- 兼容：应用代码、任务脚本和报表查询必须与迁移顺序兼容；删除类变更确认无消费方。
- 安全：SQL 全部参数化；迁移账号与应用账号分离并保持最小权限；转储与备份加密；敏感字段脱敏。
- 约束：数据库约束与应用校验共同保护不变量；不变量冲突时给出可判定的错误结果。

## 验证证据

- migration、seed、数据修复或 repository 测试命令和退出码。
- 回滚路径验证或人工核对证据；不可逆变更的恢复演练记录。
- 执行计划或慢查询证据（涉及查询与索引变更时）。
- 迁移与回填的错误率、延迟、复制延迟观测记录或人工中止判定。
- 未覆盖数据量、权限或并发风险。

## 停止条件

数据画像、备份与恢复能力、回滚路径或锁影响不清时暂停实际迁移，继续已授权的只读调查、脚本准备和本地验证；其余暂停与批准语义遵循 governance-core。不得在生产数据上临场试错。
