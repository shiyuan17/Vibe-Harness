# 发布规则

发布规则要求变更、验证、监控和回滚证据一起交付。发布完成的判据是生效版本与预期一致，且观察窗口内未触发停止阈值；本地构建通过或上传成功不等于发布成功。

本规则只定义通用发布安全边界；具体制品、签名、证明和分发方式由目标项目的贡献与交付文档管理。

数据迁移、公共契约和测试范围分别遵循 db-rules、api-rules 和 test-rules。

## 规则

- 发布证据绑定同一版本标识：版本号、来源修订和制品摘要来自同一次验证；验证对象与实际发布对象不一致时视为未验证，不得声明发布成功。
- 已发布的版本标识和制品不可移动、覆盖或复用；修复通过新版本下发，或按已记录的回滚或前滚路径处理，不改写既有发布。
- 发布前确认版本、changelog、迁移步骤、风险和监控信号。
- 失败按预先记录的回滚或前滚路径处置，不临场发明流程；该路径须在发布前核对可用。
- 不得为让发布通过而绕过失败门禁。
- 交付时写清影响范围、验证命令和未覆盖风险。

## 检查清单

- 版本：确认版本号、changelog、发布范围和目标环境；用户可见变化、破坏性变更声明、迁移和弃用路径与版本语义一致。
- 验证：发布前验证命令、人工核对和 smoke test 已记录，且针对被发布的同一版本标识运行。
- 风险：列出迁移、配置、权限、数据和用户影响。
- 回滚：记录回滚或前滚路径、命令、备份位置、兼容窗口和负责人；核对上一个可用版本制品、备份和降级开关实际可用；不可逆变更声明前滚路径和恢复能力，不假设存在回滚。
- 监控：记录生效版本核对方式、观察窗口、关键 SLI 基线、监控指标、日志位置和告警信号。
- 停止：定义取消发布、停止扩量或执行回滚的可观察阈值、判定人、升级路径和对外沟通对象。
- 凭据：确认发布凭据按最小权限、仅在发布窗口内有效，并记录轮换和失效。

## 发布证据

- 变更摘要、验证命令和退出码。
- 回滚路径和监控链接或人工核对项。
- 未验证项、延期项、发布版本标识，以及含批准人和批准依据的人工批准状态。

## 停止条件

版本、回滚、监控或高风险批准不清时暂停实际发布，继续已授权的准备与核验；授权沿用和局部暂停遵循 governance-core。达到停止阈值时先取消发布或停止扩量，再按已记录路径处理；紧急发布可以压缩验证，但必须显式声明未覆盖风险，并在发布后复盘。不得把本地构建通过当作发布成功。
