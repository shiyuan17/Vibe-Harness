# codebase-memory-mcp

codebase-memory-mcp 是宿主可提供的外部代码语义图能力，用于跨文件符号、调用链、影响面和架构分析。本规则随通用规则分发，规则存在不代表工具已安装。Vibe-Harness 不安装、配置、启动或升级该工具，不锁定版本，也不管理其索引与缓存生命周期。

## Fast Path 卡片

- 跨文件结构问题先发现宿主已提供的 MCP 工具；单文件文本、配置与日志直接使用 rg。
- 通过 `list_projects` 的实际返回值匹配当前项目根，使用返回的项目标识，不按目录名或路径算法猜测。
- 用 `index_status` 检查可用性；定位证据路径后用 `check_index_coverage` 核对覆盖与新鲜度。`ready` 只表示可读，不代表覆盖当前源码。
- 索引陈旧、覆盖缺失或工具不可用时，回退当前源码与 rg；不自动安装、升级或全量重建。
- 图是导航线索，不替代源码、测试和命令证据。空结果、未记录缺口和未读完的分页不能支撑不存在或完整覆盖结论。

以下为完整规则，仅当任务超出卡片或命中升级触发时继续读取。

## 查询与证据

1. 工具 deferred 时先按工具名发现，不因初始清单未展示就断言不可用。工具确实缺失时说明限制，不模拟调用。
2. 使用 `list_projects` 返回的项目标识和根路径确认归属；同名仓库、多个注册项、linked worktree 或影子工作区必须核对实际根，不假设共享主检出索引，也不把其他工作区的图视为当前事实。无法唯一匹配时退回源码。
3. 使用 `index_status` 查看当前服务返回的状态、时间、generation 和覆盖信号；只消费实际提供的字段，不依赖固定版本或固定工具数量。同一任务、同一工作区可复用已核对的状态；源码变化、工作区切换或 generation 变化时重新核对受影响事实。
4. 用 `search_graph` 定位精确符号，`trace_path` 追调用方向，`get_code_snippet` 读取源码，`detect_changes` 辅助判断影响面；架构或多跳关系按需使用 `get_architecture`、`query_graph`。具体参数以宿主当前工具契约为准。
5. 候选路径明确后，用 `check_index_coverage` 检查全部证据路径；否定或穷尽结论还须检查相关 scope，并读取相关分页。partial、skipped、excluded、stale、pending、unknown 或不可用覆盖，均须用源码与 rg 补齐对应范围；干净结果仅表示未记录缺口。
6. 未完成分页、未覆盖动态调用或存在无法核对的源码范围时，报告覆盖限制，不宣称不存在、死代码或完整影响面。图与当前源码冲突时以当前源码为准。

## 外部管理与安全

- 安装、MCP 配置、版本选择、自动索引/监听设置、缓存位置和资源预算由用户或宿主管理；不得修改全局配置、下载二进制、修复版本或调用已退役的项目 wrapper。
- 只读查询不等同于索引写入。`index_repository`、`ingest_traces` 会改变工具状态，须确认实际副作用与本轮授权，不因查询失败自动调用；不关闭或重新配置服务已有的自动刷新。
- `manage_adr` 等项目文件写入遵守 workspaceWrite、工作区与红区边界；`delete_project` 属索引删除，须独立核实授权、目标和影响，默认不执行。
- 不按服务器名整体放行。未知工具或参数的副作用不明确时，先查当前契约或停止该操作；不把旧版本的安全假设推广到新版本。
- 不自动清理旧缓存、数据库或其他项目的索引；卸载或升级 Vibe-Harness 不代表获得删除外部工具数据的授权。

## 降级与记忆联动

- 缺失工具或索引、覆盖不足、查询失败时，记录工具名、可观察状态、替代查询与覆盖限制，继续使用 rg 和直接源码阅读；不可用不等于源码不存在，也不放宽验收。
- `detect_changes` 返回的路径可用于提示复核关联记忆；读取记忆正文仍遵守原有授权。联动只提供导航线索，不自动改写或删除记忆。
