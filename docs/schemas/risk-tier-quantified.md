# 快速/轻量/完整 档位量化判定表

本表格提供量化标准，帮助判定变更应在哪个风险档位（快速 / 轻量 / 完整）执行。

## 判定矩阵

| 判定维度 | 快速档（L0-L1） | 轻量档（L2-L4） | 完整档（L5-L6） |
|---------|-----------------|-----------------|-----------------|
| **修改行数** | < 50 | 50-500 | > 500 |
| **文件数** | 1-2 | 3-10 | > 10 |
| **影响范围** | 单文件或单模块 | 相邻模块或层 | 跨层、跨模块、多系统 |
| **共享代码比例** | < 10% | 10-30% | > 30% |
| **API/契约变更** | 无 | 可选（向后兼容） | 是（需迁移说明） |
| **可逆性** | 完全可逆（<1分钟） | 本地可恢复（<5分钟） | 需要回滚计划 |
| **安全影响** | 无 | 低风险（审计有效） | 中高风险（需安全审查） |
| **数据影响** | 无 | 只读或临时 | 持久化或迁移 |
| **外部系统** | 无 | 可选（可降级） | 是（关键依赖） |
| **必需验证** | L0-L1（静态+Micro） | L3-L4（集成+契约） | L5-L6（E2E+完整回归） |
| **验证时长** | < 5 分钟 | 5-30 分钟 | > 30 分钟 |
| **审批** | 无需 | 代码审查 | 独立安全审查 |
| **上线前置** | 无需 | 快速通过即可 | 需要发布批准 |

## 快速档 — 指标综合判定

**同时满足以下条件**才能在快速档执行：

- 修改行数 < 50 AND 文件数 ≤ 2
- 单文件/单模块（无跨层或跨模块）
- 无 API/契约变更
- 无安全敏感操作（认证、凭据、权限）
- 无数据迁移或持久化变更
- 无外部系统依赖
- 完全可逆（撤销 < 1 分钟）
- 验证时长 < 5 分钟

**快速档验收**：
- 仅需 L0 静态检查与 L1 Micro 验证
- 快速层通过 **不能宣称集成、发布或整体完成**
- 记录实际命令与结果

---

## 轻量档 — 指标综合判定

**同时满足以下条件**才能在轻量档执行：

- 修改行数 50-500 AND 文件数 3-10
- 相邻模块或同一层级（不跨层）
- API 变更需向后兼容 + 迁移说明
- 低安全风险（审计可确认）
- 只读或临时数据操作
- 外部系统可选或可降级
- 本地可恢复（< 5 分钟）
- 验证时长 5-30 分钟

**轻量档验收**：
- 需要 L3-L4 验证（契约+集成）
- 中等层失败阻塞合并
- 需要代码审查

---

## 完整档 — 指标综合判定

**任意一个条件满足**则需完整档：

- 修改行数 > 500 OR 文件数 > 10
- 跨层、跨模块或多系统
- 公共 API/契约变更
- 安全或权限相关修改
- 数据迁移、持久化或破坏性变更
- 关键外部系统依赖
- 不可逆或需要详细回滚计划
- 验证时长 > 30 分钟
- 涉及红区文件修改
- 生产系统影响

**完整档验收**：
- 需要 L5-L6 验证（E2E+完整回归）
- 中等层失败阻塞合并
- 深度层异步允许延迟，但未取得证据前不宣称发布
- 需要独立安全审查（如适用）
- 需要发布前批准

---

## 快速判定流程

按顺序回答以下问题，首个"是"答案确定档位：

```
Question 1: 修改行数 > 500 或文件数 > 10？
  ├─ Yes → 完整档 ✓
  └─ No  → Question 2

Question 2: 涉及 API/契约变更、安全、数据迁移或红区？
  ├─ Yes → 完整档 ✓
  └─ No  → Question 3

Question 3: 跨层、跨模块或多系统？
  ├─ Yes → 完整档 ✓
  └─ No  → Question 4

Question 4: 修改行数 50-500 或文件数 3-10？
  ├─ Yes → 检查是否轻量档条件满足
  │ ├─ 是 → 轻量档 ✓
  │ └─ 否 → 完整档 ✓
  └─ No  → Question 5

Question 5: 修改行数 < 50 且文件数 ≤ 2？
  ├─ Yes → 检查是否快速档条件全满足
  │ ├─ 是 → 快速档 ✓
  │ └─ 否 → 轻量档或完整档
  └─ No  → 轻量档 ✓
```

## 示例应用

### 例1：文案修改（按钮文本）
- 修改行数：1-2
- 文件数：1
- 影响范围：单文件
- 档位判定：**快速档** ✓
- 验证：仅需 lint/typecheck
- 宣称：本地实现完成（不需集成验证）

### 例2：单元代码逻辑修改
- 修改行数：80
- 文件数：2（主文件 + 测试）
- 影响范围：单模块内
- API 变更：无
- 档位判定：**轻量档** ✓
- 验证：单元测试 + 集成检查
- 宣称：本模块实现完成（需审查）

### 例3：公共 API 重构
- 修改行数：200
- 文件数：15（API + 消费方 + 文档）
- 影响范围：跨模块（核心 + 多消费者）
- API 变更：是（需迁移）
- 档位判定：**完整档** ✓
- 验证：集成 + E2E + 发布前
- 宣称：需发布批准 + 完整回归通过

### 例4：数据迁移脚本
- 修改行数：150
- 文件数：5
- 影响范围：数据层 + 应用层
- 数据影响：持久化迁移
- 档位判定：**完整档** ✓
- 验证：迁移测试 + 幂等验证 + 恢复路径
- 宣称：需迁移完全验证 + 回滚方案

## 关键原则

1. **量化优先于感觉**：用行数、文件数和风险指标而非直觉判定
2. **多因素综合**：单个因素达到某个阈值时，档位至少升级一级
3. **边界保守**：无法明确判定时，选择更高档位
4. **宣称与验证匹配**：快速层通过不能宣称集成完成
5. **记录依据**：交付时注明档位判定依据与实际验证覆盖
