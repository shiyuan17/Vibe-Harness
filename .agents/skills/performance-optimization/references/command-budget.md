# 命令预算与层级裁剪

## 先建立成本账

每个检查记录：ID、命令、`cwd`、成本层、执行范围、证据层级、交付主张、是否确定性、估计/实测耗时、是否被复用、失败原因。总墙钟要覆盖准备、范围解析、依赖扫描、资源等待、执行、前后快照与推送证明，而不只是测试框架自报时间；并发检查的耗时和不能冒充总墙钟。

## 选择规则

- `quick`、`standard`、`deep` 是累计层；默认只执行请求层及更浅层。
- `subsumes` 只表达“同一 `cwd` 下，高层检查覆盖低层检查”。覆盖者必须实际包含被覆盖者的证据，并且不能由低层反向覆盖高层。
- 默认层计划可以裁剪已覆盖检查；`--only`、`--full` 和风险派生矩阵永不裁剪。
- 报告必须保留 `subsumedChecks`、`subsumedBy`、`selectionReasons`，让“没跑”可追溯，而不是静默消失。

## 一个实施单元

- 按验收行为选最小充分证据；quick/standard/deep 是成本层，不能代替行为证据或交付状态。
- 每个切片在能发现错误时取得聚焦反馈；不规定固定验证次数。最终组合只补尚未覆盖或已经失效的证据，不因“最终交付”自动升级 deep。
- 同一代码树不重复执行已通过的确定性检查；失败检查修复后只重跑该检查及其下游必要证据。
- 先跑格式、环境与必要编译，再跑高成本行为检查。验证期间保持候选稳定；需要改代码时先取消受影响检查并确认进程树退出。
- 项目原子检查优先消费显式参数，其次使用 Harness 冻结的 paths/base/scope，只有独立调用才自行计算。冲突或无效基线明确报错；未知或部分映射扩大，不静默换基线。

## 反面模式

- 用 `cmd1 && cmd2 && ...` 把多层命令塞进一个字符串：统计失真，失败定位困难。
- 为了“保险”同时保留 `lint` 与 `lint-changed`、`typecheck` 与 `typecheck-affected`。
- 每次提交都跑全量后端测试，而不是在合并前对最终树跑一次。
