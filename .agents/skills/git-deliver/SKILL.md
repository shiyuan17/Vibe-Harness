# 分批提交并推送

把显式调用视为对当前仓库、当前任务相关改动执行普通 Git commit 和 push 的授权；仍遵守项目 Git 规则、红区和人工确认边界。

## 执行

1. 检查工作区、当前分支、远端、upstream 和相关 diff；把任务前已有、并发产生或归属不明的改动排除，无法安全拆分时停止。
2. 按独立逻辑变更形成提交组；功能、重构、测试和文档按语义拆分，每组列出包含、排除、验证、风险、回滚和 Conventional Commit 主题。
3. 对每组运行与主张匹配的聚焦验证，只暂存明确文件或补丁，并在提交前复核 staged diff；Hook 失败时停止，不使用 no-verify。
4. 逐组提交后复核提交历史和剩余工作区；不得混入构建产物、依赖缓存、VCS 元数据或用户未归属改动。
5. 当前分支已有 upstream 时普通推送；没有 upstream 时，仅在唯一远端明确为 origin 且当前分支不是保护或共享分支时建立 origin/当前分支跟踪并推送，否则停止确认。
6. 推送失败时保留本地提交，报告原因、未推送提交和恢复命令；不回滚、不改写历史、不把失败描述为完成。

## 停止边界

- 不在 main、master、develop、release 或仓库识别出的保护/共享分支上自动推送。
- 不执行 force push、历史改写、远端引用删除、PR 创建、合并、打标签或发布；这些操作需要独立明确授权。
- 未显式调用本 Skill 时，不把普通完成请求解释为提交或推送授权。

## 交付

报告各 commit 的哈希与主题、包含和排除文件、验证结果、推送目标与结果，以及仍未提交或未推送的改动。
