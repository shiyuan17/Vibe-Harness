# 请求代码审查

请求审查时，给审查者足够上下文，让其能独立判断风险和正确性。

## 何时请求

- 合并前。
- 完成功能、bugfix、重构或高风险配置后。
- agent 生成代码需要独立复核时。
- 触及共享模块、安全、数据、发布或外部契约时。

## 请求内容

审查请求必须包含：

- 目标：本次变更要解决什么。
- 范围：主要改了哪些区域，不在范围内的内容。
- 风险：安全、数据、兼容、性能或 UI 风险。
- 验证：已运行命令、结果和未覆盖项。
- 重点：希望审查者特别关注的问题。
- 判定要求：请 reviewer 分别给出规格符合性和代码质量结论。

## 模板

```markdown
请审查这次变更。

目标：
- [一句话说明]

范围：
- [主要文件/模块]

风险：
- [高风险点；没有则写“未发现特殊高风险点”]

验证：
- `[命令]`：通过/失败，关键输出...

重点关注：
- [正确性/安全/契约/UI/性能等]

判定要求：
- 规格符合性：Pass / Fail / Cannot verify
- 代码质量：Approved / Request changes / Blocked by evidence
```

如需独立审查 prompt，可使用 `code-reviewer.md`。

优先把请求交给 `open-code-review`；不可用时回退到 `code-review-and-quality` 或独立人工 reviewer，并说明工具缺口。

## 红旗

- 只说“帮我看一下”，不提供目标或验证。
- 让实现者自我批准高风险变更。
- 没有说明未验证内容。
- 审查范围与实际 diff 不一致。
