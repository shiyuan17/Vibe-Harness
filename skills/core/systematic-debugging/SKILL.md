# 系统定位故障

先证明根因，再修改代码。

## 执行

1. 稳定复现症状，记录最小输入、环境、期望和实际结果。
2. 定位直接失败点，并沿数据或调用链追踪到最早错误状态。
3. 若存在多个合理原因，列出 2–3 个竞争性假设；每个假设记录支持证据、反证和能区分它与其他假设的最小实验。根因已由证据唯一确定时，不强行制造额外假设。
4. 一次只改变一个主要变量并收集证据；优先执行能推翻当前判断的区分实验，而不是连续尝试相似修复。
5. 用失败测试或最小复现固定问题，实施最小修复。
6. 运行聚焦回归及相关套件，确认测试没有弱化。

怀疑测试顺序污染时运行 `find-polluter.sh <file_or_dir_to_check> <test_pattern> [test_command_template]`：测试模式从当前目录解释（`./` 前缀可选），`**` 匹配零级或多级目录；`{file}` 必须是独立参数且最多出现一次，模板只支持字面量引号分组，不接受 shell 展开、管道、重定向和命令串联（默认模板 `npm test {file}`）。退出码：`0` 表示每个候选都跑过且未产生污染，`1` 表示已定位污染者，`2` 表示没有得出结论（参数非法、模板不支持、零候选、运行前污染已存在或测试命令失败），不能当作 clean 使用。不要用固定 sleep、批量猜改或重复尝试掩盖未知根因。

## 交付

报告复现、候选假设及其排除证据、根因证据、最小修复、回归结果和仍未排除的风险。

## 正反例

- 该用：「登录偶发 500，日志只留一次堆栈」——根因未定，需要能推翻判断的区分实验。
- 根因已知：证据已唯一确定根因，或只是实施既有结论的机械修复，直接改并跑聚焦回归，不重新制造假设。
- 工具不可用：无法运行复现时只交付静态推导与下一步实验，明确标注「未复现」，不声称已证明根因。
