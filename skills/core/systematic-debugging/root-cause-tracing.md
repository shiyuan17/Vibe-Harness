# 根因追踪

根因追踪的目标是找到最早导致坏状态进入系统的位置，而不是停在报错点。

## 适用时机

- 错误发生点只是症状。
- 数据在多层调用后才坏掉。
- 测试污染、状态泄漏或竞态难以定位。

## 流程

1. 观察症状：记录错误、输入、输出和复现步骤。
2. 找直接原因：是哪一行、哪一个值或哪一个状态错了。
3. 追问调用者：谁传入了这个值，为什么它被允许进入。
4. 继续向上：直到找到最早的错误假设、缺失校验或错误触发。
5. 用最小测试锁定根因。

## 技巧

- 在边界处记录值和调用栈。
- 对异步路径记录时间顺序和状态变更。
- 对测试污染使用二分或 `find-polluter.sh`。
- 一次只改一个观察点，避免制造新变量。

## 结论格式

```text
症状：...
直接原因：...
根因：...
证据：...
修复点：...
回归测试：...
```
