# 条件式等待

异步测试和浏览器验证应等待“条件成立”，而不是等待固定时间。

## 使用时机

- UI 更新、请求完成、队列处理或文件生成需要时间。
- 测试偶发失败。
- 代码里出现 `sleep(1000)`、`setTimeout` 或固定等待。

## 核心模式

```typescript
await waitFor(() => {
  expect(screen.getByText('Saved')).toBeVisible();
});
```

等待条件应该描述真实完成状态：

- 元素出现或消失。
- 请求完成且状态正确。
- 文件存在且内容符合预期。
- 队列为空。
- 状态机进入目标状态。

## 避免

- 用固定 sleep 掩盖竞态。
- 等待过宽条件，例如“没有报错”。
- 超时后不输出诊断信息。
- 在生产代码中加入只为测试服务的等待。

## 固定等待何时可用

只有在需求本身就是时间，例如 debounce、动画持续时间、限流窗口时，固定时间才是被测行为的一部分。
