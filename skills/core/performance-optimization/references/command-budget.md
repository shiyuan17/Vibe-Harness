# 命令预算与层级裁剪

## 先建立成本账

每个检查记录：ID、命令、`cwd`、成本层、是否确定性、估计/实测耗时、是否被复用、失败原因。总墙钟要覆盖进程启动、依赖解析和锁等待，而不只是测试框架自报时间。

## 选择规则

- `quick`、`standard`、`deep` 是累计层；默认只执行请求层及更浅层。
- `subsumes` 只表达“同一 `cwd` 下，高层检查覆盖低层检查”。覆盖者必须实际包含被覆盖者的证据，并且不能由低层反向覆盖高层。
- 默认层计划可以裁剪已覆盖检查；`--only`、`--full` 和风险派生矩阵永不裁剪。
- 报告必须保留 `subsumedChecks`、`subsumedBy`、`selectionReasons`，让“没跑”可追溯，而不是静默消失。

## 一个实施单元

- 实施期间每个单元一次正式 quick 验证。
- 最终交付只做一次 deep 或合并后树复核。
- 同一代码树不重复执行已通过的确定性检查；失败检查修复后只重跑该检查及其下游必要证据。

## 反面模式

- 用 `cmd1 && cmd2 && ...` 把多层命令塞进一个字符串：统计失真，失败定位困难。
- 为了“保险”同时保留 `lint` 与 `lint-changed`、`typecheck` 与 `typecheck-affected`。
- 每次提交都跑全量后端测试，而不是在合并前对最终树跑一次。
