# Bug 查找审查

只读审查常见缺陷，不修改源码、配置、依赖、数据库或外部系统。

## 执行

1. 读取规则、需求/验收、入口、配置、契约、模型、状态定义、测试和相关变更。
2. 建立“需求→流程→状态→数据→事件/缓存→接口”关系链，检查分支、边界、终态、回滚、重复执行、事务与一致性。
3. 用已有测试、脚本、fixture 或浏览器执行最小关键路径；记录命令、输入、期望和实际，一次验证一个假设。
4. 工具不可用时停止运行层；静态推导不得声称已复现。继续检查调用方和消费方，确定影响范围。

重点覆盖业务逻辑、流程断链、功能缺失/多余、需求不符、非法状态迁移、数据一致性，以及接口参数、鉴权、错误、超时、重试、幂等和响应契约。

## 报告

按严重度列出位置、触发条件、期望/实际、证据、影响、根因假设、最小修复方向和回归测试；结尾列未覆盖风险。证据标记为 **已确认事实**、**静态结论**、**待验证假设** 或 **验证受阻**，不把猜测当缺陷。
