# 深度问题发现审查

`find-question` 是跨层一致性与潜在缺陷审查 Skill。它只读项目，不修改源码、配置、依赖、数据库或外部系统；目标是发现“能运行但不合理、会静默失效或会绕过控制”的问题。

## 启动

1. 若存在审查包，先读取 `vb find question --project <path>` 的输出；否则声明审查范围、基线 commit、工作区状态、审查档位和输出位置。
2. 跨文件按项目导航规则建立上下文；图工具可用时核对项目、索引状态和证据覆盖，覆盖不足回退源码检索；空检索不证明无消费者。
3. 按单批一个模块或一组相关文件推进；超出范围先列分批计划和未验证边界。
4. 默认 deep；quick 单链路抽查，standard 单域核对，deep 跨模块分批。每档均判断八类风险适用性；跳过项明确登记，不自动扩大测试成本或线上权限。
5. CLI 不可用时直接读取本 Skill 与项目契约开展审查，不安装 CLI。CLI 的 JSON/Markdown 是 planned 审查包，不含已完成 findings；默认只输出会话报告，用户明确要求归档才写项目内报告，不写红区。

## 核心审查

对每个字段、规则和控制点建立“契约→入口→消费”三链矩阵，并主动证伪每个候选。断链只登记候选；外部消费、兼容保留、计算字段或有意禁用不是自动成立的缺陷，须证明可达行为违反契约或不变量。

- **契约与字段**：类型、必填、空值、枚举、单位、精度、默认值、版本兼容和错误契约。
- **逻辑与规则**：冲突条件、优先级、不可达分支、恒真/恒假校验、阈值、关键词拼接和隐式降级。
- **引用与消费**：空引用、过期 ID、悬空生产者/消费者、无消费配置、隐藏入口、默认值掩盖和未接线功能。
- **数据一致性**：单一事实源、读写对称、事务边界、缓存失效、重试幂等、并发、事件顺序和最终一致性。
- **配置与发布**：环境漂移、Feature Flag、未知键、默认值、灰度、回滚和密钥/敏感信息泄漏。
- **授权与控制面**：认证、对象级/字段级授权、租户边界、读写对称、拒绝默认值、审计和导出/导入旁路。
- **生命周期**：状态机合法/非法迁移、终态、撤回、删除、恢复、迁移兼容和重复执行。
- **可观测性**：静默吞错、日志/指标/审计缺口、告警不可达和恢复路径缺失。

## 证据与证伪

- 先摘录原文，再写判断；每条 finding 必须有可复核路径、行号、符号、契约条目或命令输出。
- 证据状态只用：已确认事实、静态结论、待验证假设、验证受阻。
- 追查替代写入入口、其他消费方、配置开关、默认值、测试覆盖和异常恢复；被证伪的候选不进入问题清单。
- 静态推导不得写成运行时已复现；工具不可用时说明受阻原因。

## 报告

沿用项目的 docs/rules/review-report.md 与已安装的 finding-report.md 模板：每条 finding 填满六字段、保持 `<DOMAIN>-F<nn>` 连续编号和 P1/P2/P3 判据。现象写触发条件、实际/期望及被破坏的不变量；边界写证伪结果；影响区分实证和推断；建议给最小可逆改动与关闭验证。缺少业务判据的“不合理”只作为待验证假设，不按偏好报错。

报告结尾必须包含：

1. 已核对正确项及证据锚点；
2. 未验证边界与验证受阻原因；
3. 易被忽略清单；
4. 按“数据/控制面→入口/阻断→字典/配置/生命周期→工程卫生”排序的统一处理建议；
5. 面向每个 finding 的优化调整计划、回归验证和监测建议。

使用 `$find-question` 或 `Vb Find Question` 可显式调用；`vb find question` 只生成审查包，不代表审查已经完成。
