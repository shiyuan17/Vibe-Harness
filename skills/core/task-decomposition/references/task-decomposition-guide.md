# Task Decomposition Guide

`task-decomposition` Skill 的操作参考：回答要不要拆、按什么拆、节点怎么声明、什么时候能派发，以及单节点提示词怎么写。

本文件是操作参考；节点字段、状态与 ready 规则以 docs/rules/ai-collab-rules.md 为准，授权与验证以 docs/rules/governance-core.md 为准，冲突时规则优先，不另立第二真值。

规划只读：Plan 不构成新增写入、提交、推送或外部授权；本 Skill 不自动创建 Goal、不派发子 Agent、不执行后继节点。用户已授权实施的计划在宿主允许执行后持续推进，不追加形式化最终确认。

## 拆分判定

按实际依赖、写入隔离和独立并行收益判断，不按信号数量、公共契约或文件数量判断。

拆分轴：按可独立验收的交付切片（垂直切片）组织节点，每个节点结束时留下一个可观察、可验证的增量；不按技术层（模型／服务／接口／界面）拆，也不按文件数量拆。

不构成拆分理由：公共契约、Schema、迁移兼容、混合重构、文件数量或里程碑数量本身。单 Agent 可稳定完成时直接实施；只有实际采用两个以上协作单元时才维护 Task DAG。

共享契约：API、Schema、迁移或行为契约指定唯一写入 owner 并建立显式依赖，消费方按顺序接入；无法证明隔离时按冲突处理，不得仅凭路径不重叠就并行。

并行收益判据，满足才拆：

- 拆分是否缩短关键路径；并行节点落在同一条关键路径上时只增加协调成本。
- 写节点的合并、复核与回归成本是否可控。
- 只读探查可宽 fan-out（软上限 8），写节点保持窄（软上限 5）；软上限可被宿主容量、限流和预算进一步压低。
- 上下文高度重叠、强顺序依赖或需要共享同一份推理上下文的任务不适合拆分；多 Agent 的 token 成本显著高于单 Agent。

需要给出判断时，Split Decision 至少包含：决定（拆或不拆）与采用的策略、依据事实、被否方案与原因、预计并行收益与主要协调成本、写入归属与共享资源（共享契约 owner、writeScope、resourceLocks，没有则写 None）。

## 拆分策略选择

按子任务形态选策略：能顺序完成就不并行，能单 Agent 完成就不拆分。

- 固定顺序链：可清楚切成固定步骤且每步消费上一步输出时，不建 DAG，按顺序执行，必要时在步骤之间设检查点。
- 独立子任务并行：子任务之间没有共享写入、没有相同 resourceLocks 时按批次并行。
- 同任务多视角独立验证：需要独立判断时，用只读、独立上下文的节点对同一产物分别核验；分歧用事实与验证消解，不用多数票覆盖证据。
- orchestrator-worker：子任务数量与形态事先不可预测时，由父 Agent 按轮次依据当前事实决定下一批节点，不预生成一整张长 DAG。
- evaluator-optimizer：产物需要迭代（生成→评估→修订）时，把循环与退出判据写进计划，而不是把每一轮都建成新节点。

## Goal 与节点分层

Goal Brief 描述期望终态与整体验收，不是 DAG 节点，也不占用节点标识；Task DAG 只包含可执行节点（kind 为 read、write 或 aggregate）。

只输出当前请求需要的部分：不强制 Goal Brief、节点表、并行批次、关键路径或里程碑全套格式。用户只要求单节点执行提示词时，只输出该 ready 节点的提示词，其余节点保持非 ready。

## 节点契约与可选字段

字段名与取值以规则为准：id、kind、output、dependsOn、trigger、writeScope、resourceLocks、verification、result。

- 节点声明必要依赖、输入、写入归属（writeScope）、共享资源（resourceLocks）、可验收输出与验证方式。
- 只读节点的 writeScope 为空；trigger 默认 all_success。
- result 使用 pending、ready、running、unverified、succeeded、failed、blocked、skipped 或 cancelled。
- unverified 与 blocked 是非终态；Linear 的 Canceled、Duplicate、Won't Fix 只作外部终态并按非 succeeded 处理。
- skipped 只用于没有任何后继依赖其成功的节点；会阻塞后继的节点不得标记 skipped。

writeScope 只接受项目相对精确路径，或末尾为 `/**` 的目录范围；拒绝绝对路径、UNC、空路径、`..` 与其他复杂 glob。

可选字段，仅长任务填写，普通单 Agent 任务不填：节点超时、最大尝试次数、取消、退避、资源与 token 预算。

派发前可用 `pnpm task-dag check --file <dag.json> [--require-ready]` 校验节点契约、依赖边与环、writeScope 与 resourceLocks 冲突；该命令只校验结构与隔离事实，不替代人读判断。

## Ready 与完成判定（质量检查）

Ready 清单，生成或派发节点提示词前逐项确认：

- 直接前驱按自身 trigger 全部满足；依赖未成功时该节点保持非 ready。
- 不存在 writeScope 重叠或 resourceLocks 相同的并发写节点；共享契约由唯一 owner 写入。
- 输入、依赖证据与已冻结的契约快照可用。
- 验收判据与需要返回的证据形态已写明，writeScope 写法合法。

完成判定：验证证据必须在最后一次实质修改之后取得；未运行的必要验证记为 unverified，不能支撑完成声明，也不得把检查通过简化为构建或 lint 通过。

fail-closed 结果：

- 自依赖、有向环、不可见前驱或依赖清单不完整：报告 offending edge 或 path，明确需要修订 DAG，不选 ready 节点。
- 共享契约的 owner、兼容性或迁移决定未决：受影响路径记为 blocked 并列出缺失的决定，不得臆造契约与归属，也不得先派发消费方。

## 按比例验证

验证要求与节点风险和完成主张成比例，不默认全仓检查或全矩阵：

- 节点提示词只携带该节点变更路径的聚焦验证——按路径自动选择受影响的检查层（本项目为 `pnpm verify:focused --run`），不携带全仓 check；全仓检查保留给阶段收尾、合并前或显式高风险节点。
- e2e、matrix 与生命周期 smoke 只进入发布边界、CI full 门禁或高风险节点的验收判据；普通节点不要求，也不因目录名自动触发。
- fan-in 父节点在合并后跑一次集成验证覆盖子节点的合并面；集成验证不在每个子节点重复。
- 任务锚点的 riskLevel 是建议层：快速/轻量档的单元完成主张由快速层收据支撑，完整档由 standard 层收据支撑；只有显式收尾门禁（如 `worktree land` 验证门）把它升级为硬门禁。
- Ready 判据与验收写"必要验证"——与该节点实际变更路径和完成主张匹配的检查集；影响无法归因时按高风险处理。

## 节点执行提示词（宿主无关）

每个节点提示词自包含四要素：

- 目标：该节点要达成的可观察结果。
- 输出格式：交付物形态与返回结构，例如改动清单、结论与验证输出。
- 可用工具与来源：需要的能力或来源，而不是具体 CLI 或工具名。
- 边界：明确做什么，以及明确不做什么（越界路径、不修改的区域、不代替父 Agent 做的决定）。

另需写明：自包含输入（含已冻结的共享决策与契约快照）、writeScope 允许修改范围、验收判据、需要回传的验证命令与退出码、节点标识与当前授权范围。

宿主无关指描述所需能力（读写、检索、只读网络等）而不绑定具体命令，也不假设宿主提供 Goal API、后台调度或持久化状态服务。一次只给一个 ready 节点的提示词，输出停在提示词边界，不激活 Goal、不派发、不执行后继。

## 派发、失败与交接

每次派发 write 节点前重新核对观察基准：依赖集、writeScope、resourceLocks、HEAD 与工作区身份；仅当宿主或 Linear 提供结构 hash 或变更游标时才一并比较，本地人读计划逐项核对事实，不新造 hash 或 schema。基准变化时暂停受影响节点及其后继并重算 ready 集合。

失败处理：测试失败在节点范围内查因、修复并重跑；瞬时故障有界重试，权限与安全拒绝不得重试绕过；非幂等外部写入结果不明时先重读真实状态。缺少权限、依赖或必要产品决定时回报父 Agent，独立且已隔离的工作可以继续。

交接内容：节点结果、实际修改文件、base/head、验证命令与退出码、未决风险与阻塞原因。交接信息只是人读证据，不构成授权。

fan-in：父 Agent 在合并后重新读取工作区与实际 diff，核对写入归属、共享契约与验收，并运行集成验证；不得只汇总子节点自报。父 Agent 按整个请求的授权和验收继续编排，不因节点完成要求用户重复说“继续”。

## 反模式

- 按文件或按技术层拆节点，而不是按可独立验收的交付切片拆。
- 给每一步都建节点：三步顺序任务被 DAG 化，只增加协调成本。
- 节点没有可验收输出或没有验收判据，完成与否无法判定。
- 多个节点写同一份共享契约，或依赖路径不重叠就默认可并行。
- fan-out 超过复核带宽、token 预算或软上限。
- 只写里程碑或阶段名，不写可执行动作、文件范围与验证方式。
- 用 DAG 掩盖未决的产品决定或未定的契约 owner。
- 把未运行的必要验证写成已完成，或把 skipped、unverified 当作成功。
- 每个节点都要求全仓检查或全矩阵验证，验证成本与节点风险不成比例。

## 示例

计划：“把配置读取迁移到新的 settings 模块，两个模块都要改，且接口契约未定”。

- 拆分判定：契约未定，不先拆消费方；先由一个节点冻结契约并迁移模块 A，再让模块 B 依赖其结果。两步之间存在接口耦合，不属于可并行切片，因此保持顺序执行。
- Split Decision：决定＝拆为两个顺序节点，不并行；依据＝共享契约唯一写入 owner 加显式依赖；被否方案＝模块 A 与 B 并行，冲突点是同一契约会出现多个写入者；并行收益＝无关键路径缩短；共享资源＝契约相关写入由 n1 独占。
- 节点表（示例）：

| id | kind | output | dependsOn | writeScope | resourceLocks | verification |
| --- | --- | --- | --- | --- | --- | --- |
| n1 | write | 新 settings 读写接口与模块 A 迁移 | None | `src/settings/**`, `src/module-a/**` | contract:settings | `pnpm test:unit` 退出码 0 |
| n2 | write | 模块 B 接入新接口 | n1 | `src/module-b/**` | None | `pnpm test:unit` 退出码 0 |

此时只有 n1 是 ready 节点。n1 的提示词示例：

- 目标：产出新的 settings 读写接口，并让模块 A 只通过该接口读取配置。
- 输出格式：改动文件清单，加上接口签名与迁移前后的行为差异说明。
- 可用工具与来源：读写仓库文件、检索现有配置调用方、运行项目单测。
- 边界：只修改 `src/settings/**` 与 `src/module-a/**`；明确不做什么——不改 `src/module-b/**`，不改变现有配置项的默认值，不替父 Agent 决定 B 端迁移顺序。
- 输入：现有配置读取实现、调用方清单、已冻结的接口契约快照（方法名、参数与错误语义）。
- 验收：`pnpm test:unit` 退出码 0，且新增接口的调用方测试覆盖模块 A 的全部读取路径。
- 回传：结果、实际修改文件、base/head、验证命令与退出码、未决风险与阻塞原因。
