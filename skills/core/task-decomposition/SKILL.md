# 任务拆解

单一目标、单一写入范围和一次验证闭环可以完成时，保持“单任务”。命中多 Agent、多个 worktree、完整档位、高风险、多个独立交付物或可并行写入范围时，拆成“父任务”和“子任务”。

父任务写清目标、验收、依赖、冲突和集成验证。每个子任务只承担一个最小可审查闭环，并在完整流程控制中填写父任务编号、责任角色、写入范围、依赖任务、冲突任务、并行安全、时间盒分钟、停止条件、回滚方案和核验者。

无法判断写入范围或冲突时串行执行。不要把“写测试”“改一行”或“运行命令”等机械步骤单独拆成子任务。`subagent-driven-development` 不可用时回退为当前执行者按依赖顺序逐项验证。
