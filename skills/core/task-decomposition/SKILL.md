# 任务拆解

先判断是否需要父子任务，再把大任务拆成能独立验证的子任务。

## 模式判断

1. 单一目标、单一写入范围、一次验证闭环即可完成时，小任务直接输出 `single`。
2. 命中多 agent、多个 worktree、完整流程（`Full`）、高风险、多个可独立审查交付物，或写入范围可并行拆分时，输出 `parent` + `child` 列表。
3. 无法判断写入范围、依赖或冲突关系时，先澄清，不要假装可并行。

## 子任务粒度

1. 写清 parent 目标、成功标准、非目标、依赖、冲突和集成验收。
2. 每个 child 只承担一个最小可审查闭环，目标应在约 5 分钟内完成或暴露阻塞。
3. 为每个 child 指定写入范围、验证命令、停止条件、回滚方式和交付证据。
4. 标出依赖顺序：哪些可以并行，哪些必须串行。
5. 给高风险 child 标记红区、review 或人工确认需求。

不要把“实现整个功能”当作单个 child。无法独立验收的子任务继续拆，但子任务不能拆得太细；不能把机械步骤拆成 child，例如单独的“写测试”“改一行”或“运行命令”，除非该步骤本身就是可交付、可验收的完整目标。
