# 视觉伴侣指南

视觉伴侣用于在头脑风暴中展示 mockup、流程图、布局对比或视觉方案。它不是默认步骤；只有当“看见”明显比文字更清楚时才使用。

## 何时使用

使用：

- 布局、信息架构或流程图需要对比。
- 设计方向、组件层级或视觉密度需要一起看。
- 用户需要在几个界面方案中选择。

不使用：

- 需求、范围、成功标准等文字决策。
- 纯代码、API 或测试计划讨论。
- 用户没有同意打开视觉伴侣。

## 启动

用户同意后启动：

```bash
skills/core/brainstorming/scripts/start-server.sh --open --project-dir .
```

脚本会返回类似信息：

```json
{
  "type": "server-started",
  "port": 52341,
  "url": "http://localhost:52341/?key=ab12...",
  "screen_dir": "/path/to/project/.loopengine/brainstorm/.../content",
  "state_dir": "/path/to/project/.loopengine/brainstorm/.../state"
}
```

在 Codex 环境中，如需跨 turn 保持进程，按平台工具支持以前台/后台方式启动；记录返回的 URL 和目录。

## 使用循环

1. 明确本轮要展示的问题。
2. 在 `screen_dir` 中写入 HTML/CSS/JS 内容片段或页面。
3. 打开或刷新浏览器查看。
4. 向用户说明当前画面代表什么，并询问具体选择。
5. 根据反馈迭代或回到文字讨论。

每次只展示一个决策点，避免把多个无关选择塞进同一屏。

## 内容片段原则

- 展示真实结构、密度和状态；不要做装饰性占位。
- 文案应接近产品真实语境。
- 对比方案要并排且标签清楚。
- 保持可读：字体、间距、对比度和响应式布局要可靠。
- 不把视觉伴侣产物当作最终实现代码。

## 可展示内容

- 页面线框。
- 组件状态。
- 用户流程图。
- 信息架构。
- 多方案视觉比较。
- 复杂系统关系图。

## 收尾

当用户完成选择后，把决策写回设计规格：

- 选择了哪个方案。
- 放弃了哪些方案，为什么。
- 视觉约束或实现注意事项。
- 仍需后续验证的点。

不要让浏览器内容成为唯一记录；规格文档才是后续计划的依据。
