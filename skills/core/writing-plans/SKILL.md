# 编写实现计划

把已认可规格转成另一位工程师无需自行决策即可执行的计划。

## 前置

- 规格已明确目标、范围、行为、接口、风险和验收。
- 先定位真实文件、现有模式和验证命令；不凭想象写路径或签名。
- 多个独立子系统拆成独立计划，明确依赖顺序。

## 计划内容

使用 `references/plan.md`，每个任务写清：

1. 新建、修改和测试文件的精确路径与职责。
2. 消费和产出的函数、类型、命令、模板或契约。
3. 失败测试、预期失败原因、最小实现和通过验证。
4. 写入边界、禁止动作、风险、停止条件和回滚方式。
5. 可验证产物及后续任务依赖。

不得出现“待定”“补充细节”“写合适测试”等占位。复杂代码可给精确接口和伪代码，不复制整份实现。

单一目标、单一写入范围和一次验证闭环保持为单任务；命中多个独立交付物、多个 worktree、高风险或可并行范围时，在计划中声明父子任务、依赖、冲突、时间盒、停止条件、回滚和集成验证。不要把写测试、改一行或运行命令拆成独立子任务。

## 自审与交接

- 每项需求映射到任务和验收证据。
- 前后任务的名称、类型和契约一致。
- 每个任务都有命令、预期结果和失败处理。
- 使用 `plan-document-reviewer-prompt.md` 检查遗漏。

执行默认使用 `executing-plans`。`subagent-driven-development` 仅在已安装且写入范围可隔离时作为可选方式；不可用时回退到当前 session 的 inline execution。
