# 澄清示例

对照"好澄清"与"坏澄清"，校准问什么、跳过什么。

## 好澄清（阻塞且高影响）

请求：给工作区增加删除和导出功能，两者都未指定语义。
- 删除是软删除还是硬删除？推荐软删除（可恢复）；硬删除不可逆。影响：数据恢复与合规。
- 导出格式是 JSON 还是 CSV？推荐 JSON（保留类型）；CSV 需额外约定转义。影响：下游消费方。

理由：答案改变数据语义和公共接口，不可从仓库发现，互不依赖，同轮合并两题。

## 坏澄清（应为可发现或可逆）

请求：把超时从 10 秒改成 20 秒。
- 问"超时配置在哪个文件？"——坏，可从仓库 grep 发现。
- 问"用哪个常量名？"——坏，实现细节，沿用仓库惯例。
- 正确做法：grep 定位、直接改、跑受影响测试。

## 坏澄清（应为安全审批）

请求：把这个已批准的行为部署到生产。
- 问"你希望现在部署还是稍后？"——坏，把不可逆生产动作包装成普通产品偏好。
- 正确做法：作为安全审批显式请求人工确认。

## 依赖型（分轮）

请求：先定订阅档位模型，再定各档限额。
- 第一轮只问档位模型；限额依赖档位答案，留到第二轮。
- 不要同轮问两题，因为限额选项随档位变化。
