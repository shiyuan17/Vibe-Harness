# 测试驱动开发

核心门禁：没有先观察到正确原因的失败，就不能证明测试能捕获缺失行为。

## Red-Green-Refactor

1. Red：写一个描述单一行为的最小测试，优先真实代码而非 mock。
2. 运行测试，确认它因目标行为缺失而失败；语法、环境或夹具错误不算 Red。
3. Green：只写让该测试通过的最小实现，不顺带增加功能或抽象。
4. 重新运行该测试及相关测试，确认无错误和警告。
5. Refactor：通过后再消除重复、改善命名和结构，并持续保持绿色。

## 缺陷修复

先用测试复现用户可见症状，再修复根因。测试必须在修复前失败、修复后通过；不能只断言 mock 被调用。

## 停止信号

- 测试先天通过：断言没有覆盖新行为，重写测试。
- 必须 mock 所有依赖：边界可能耦合过重，先简化接口。
- 测试设置大于行为本身：提取夹具或缩小单元。
- 实现先于测试：回退实现，从失败测试重新开始。

测试替身和夹具的反模式见 `testing-anti-patterns.md`。无法自动化时必须获得例外确认，并记录可重复的人工验证。
