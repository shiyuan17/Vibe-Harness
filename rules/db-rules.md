# DB 规则

DB 规则用于保护数据完整性、迁移安全、兼容性和回滚能力。迁移前必须检查现有数据形状、幂等性、锁影响、事务边界和备份策略。

## 规则

- 迁移前确认数据形状、幂等性、锁影响和备份策略。
- 读写路径要覆盖空值、重复、并发和权限失败。
- 交付时写清影响范围、验证命令和未覆盖风险。

## 检查清单

- 数据形状：确认现有数据、空值、重复、历史异常和规模。
- 迁移：说明幂等性、锁影响、运行顺序、降级行为和回滚路径。
- 读写：覆盖并发、权限失败、部分失败和事务边界。
- 备份：高风险数据变更必须记录备份或恢复策略。
- 兼容：应用代码、任务脚本和报表查询必须与迁移顺序兼容。
- 约束：数据库约束与应用校验共同保护不变量；并发写入必须定义冲突结果和重试边界。

## 验证证据

- migration、seed、数据修复或 repository 测试命令和退出码。
- 回滚路径验证或人工核对证据。
- 未覆盖数据量、权限或并发风险。

## 停止条件

数据形状、备份、回滚路径或锁影响不清时停止；不得在生产数据上临场试错。
