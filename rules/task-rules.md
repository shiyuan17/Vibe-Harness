# Task Rules

任务是可验证、可恢复的工作单元；目标执行（`goal`）是一次执行尝试，不是状态真值。

## 状态模型

使用三层状态：

| 字段 | 示例 | 说明 |
| --- | --- | --- |
| `phase` | `clarify` / `ready` / `execute` / `review` / `done` | 生命周期阶段 |
| `status` | `idle` / `running` / `blocked` / `waiting_human` / `failed_validation` | 当前执行状态 |
| `resolution` | `open` / `done` / `wont_do` / `duplicate` | 结果判定 |

`done` 只能来自验证证据和验收门禁；实现 Agent 不能自证高风险最终通过。

## 父任务 / 子任务

- 默认采用兼容模式：小任务保持 `single`，大任务才拆成 `parent` / `child`。
- 小任务保持 `single` 的条件：单一目标、单一写入范围、一次验证闭环即可完成；小任务不需要父子任务模式。
- 父子任务触发条件：多 agent、多个 worktree、完整流程（`Full`）或高风险、多个可独立审查交付物、写入范围可并行拆分。
- 父任务负责目标、边界、拆分完整性、依赖和完成校验。
- 父任务负责任务统筹、依赖排序、冲突处理、集成验收和 merge-back 状态。
- 子任务负责一个可观察目标，必须有停止条件、验证命令和回滚方案。
- 父任务作为编排者时不得直接实现业务改动；父任务不得直接改业务实现。
- 子任务达到停止条件后立即交付；额外发现记录为后续子任务或阻塞项。
- 子任务必须是最小可审查闭环，包含可执行、可测试、可审查的交付物。
- 子任务不能拆得太细；不能把“写测试”“改一行”“运行命令”这类机械步骤拆成 child，除非该步骤本身就是可交付、可验收的完整目标。
- 子任务应在约 5 分钟内完成或明确阻塞；超过时间盒时记录阻塞、证据和下一步最小动作。
- 父任务完成前必须确认所有子任务验证、审查、merge-back、集成验证和剩余风险记录完成。

## 最小执行卡

执行 child 时至少包含：

- 目标
- 父任务 ID
- 状态字段：`phase` / `status` / `resolution`
- 下一步动作：`nextAction`
- 验收标准和非目标
- 停止条件
- 验证命令
- 回滚方案
- 写入范围
- 禁止动作
- 依赖 / 冲突关系

## 完成规则

任务完成前必须满足：

- 验收标准已覆盖；
- 验证命令有退出码或人工核对证据；
- worktree 已 merge-back；
- 审查或人工确认门禁已满足；
- 交接记录包含剩余风险和恢复提示。
