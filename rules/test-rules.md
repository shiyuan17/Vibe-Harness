# 测试规则

测试范围随风险和影响面扩大。先选择验证范围，再选择命令；普通对话和只读诊断不是默认测试触发条件。

## 验收矩阵

| 任务类型 | 最小验证 | 必填证据 | 升级条件 |
| --- | --- | --- | --- |
| 普通对话 / 只读诊断 | 默认不运行测试；记录已核对的事实 | 核对来源、结论和剩余风险 | 用户要求测试、需要复现问题、开始改动或必须取得运行时证据 |
| 文档 / 治理 | markdown、governance 或 pack validation | 命令、退出码、关键输出 | 安装器、hook、CI 或模板行为变化 |
| 小型实现 | 聚焦单测 + 适用 lint/typecheck | 命令、退出码、失败/通过摘要 | 共享行为、跨层或外部契约 |
| 共享行为 | 回归测试 + 扩大检查范围 | 覆盖的验收标准和命令输出 | 多调用方或公共接口 |
| UI | 组件测试 + 浏览器关键状态 | 截图、浏览器步骤或像素/状态证据 | 布局、交互、响应式或长文本风险 |
| API / 契约 | mapper/service 测试 + 契约核对 | 请求/响应形状和错误路径证据 | 外部系统或跨仓依赖 |
| Security / DB | 正向、负向、权限/迁移/回滚测试 + 独立审查 | 命令、退出码、Review 结论 | 红区、生产或数据破坏风险 |

## 选择与升级

- 测试前在任务确认或验证记录中写明验证范围和升级理由。行为改动先运行受影响范围的聚焦测试；聚焦测试只能支持该范围内的结论。
- 全量测试不是默认验证。仅在用户明确要求、目标项目将其配置为门禁、发布 / CI、安装器、运行时、hook、模板行为变化，或跨模块高风险变更需要时运行。
- 共享行为、跨层或公共接口先扩大回归范围；无法确定影响面时先收集调用方和聚焦证据，再决定是否升级全量测试。
- 发布包自身的贡献指南可以另设必跑门禁；该门禁不因安装而继承为目标项目普通会话的默认测试。

## 证据

记录命令、退出码和关键输出。不要用历史运行或片段日志声称通过。未验证项必须显式写入交付包，说明原因、风险和下一步。

## 完成标准

- 每条验收标准至少对应一个验证证据。
- 验证命令必须是当前工作区新运行的结果。
- 退出码非 0 时不得声明通过。
- 测试覆盖不足时降低完成声明或进入审查 / 交接。
