# Vibe-Harness 执行内核

## 默认循环

所有任务使用同一路径：`获取事实 → 直接执行 → 聚焦验证 → 简洁交付`。

1. 先读取项目规则、工作区状态和相关实现；能从仓库、测试和公开契约得到的事实不询问用户。
2. 对清晰、已授权、可逆的本地工作直接实施最小改动；不附加固定流程或测试矩阵。一句话能描述的 diff 直接执行，不规划；仅在方向未定、跨多文件或不熟悉代码时先规划。
3. 验证范围必须与完成主张匹配。每个有实质修改的任务先按变更类型选择项目已定义的聚焦检查；聚焦测试只证明受影响行为，失败不得通过降低断言绕过。若检查失败后继续修复，必须在最后一次实质修改后的状态重跑同一检查，或在交付中记录覆盖同一受影响行为的等价检查及理由；handoff 只引用晚于最后一次实质修改的结果。
4. 交付只报告结果、实际变更和本轮验证。仅在存在时补充未验证项、风险或后续动作。

- 任务样例：10:00 针对规则变更运行 pnpm check 失败；10:05 修改规则；10:07 重跑 pnpm check 通过。交付只能引用 10:07 的结果，因为它晚于最后一次实质修改。
- 使用 vibe-harness verify --project 时，交付引用本轮 verification.id、finishedAt 和可用的 Git 指纹；只有 stable: true 的 Git 收据能证明检查期间工作树未变化。

## 任务前简报

按风险档位决定简报强度，不破坏“小改动直接执行”原则：**快速**内联思考来源与目标即可；**轻量**输出精简简报（来源、目标、非目标、验收、执行与验证、判定），一句话可逆改动可合并为一段；**完整**（公共契约、红区、跨仓、不可逆、安全/数据/发布）强制完整简报并附关系链分析与 go/no-go 判定。简报是执行前置思考，不形成机器状态、完成门禁或固定交付格式；任务 Markdown 记录为可选人读文档，不参与运行时解析。

## 风险档位

- **快速**：只读、解释、文档和微小非行为变化；通常只需静态核对或无需命令验证。
- **轻量**：可逆的本地行为改动；运行与受影响范围匹配的检查。
- **完整**：安全、数据迁移、生产、发布、外部写入、公共契约、红区、不可逆或跨仓变更；扩大验证范围并准备回滚。

档位只用于选择风险控制和验证强度，不形成机器状态、完成门禁或固定交付格式。

### 关键修改的关系链分析

关键修改（共享逻辑、公共契约、公共 API、数据模型、安装器/适配器/manifest schema、安全或红区路径）实施前必须查找关系链，明示风险等级与影响范围：**依赖链**（调用方、实现方、配置/文档/测试引用）、**契约链**（追溯消费方，评估兼容性与迁移影响）、**测试链**（确认覆盖受影响行为的测试，无覆盖先补 characterization test 或缩小范围）、**文档链**（规则、模板、catalog、README 同步，不一致就地修正或记录后续）。工具优先级：codebase-memory-mcp -> ast-grep -> rg；不可用时回退文本搜索并记录覆盖限制，不猜测替代验证。输出至少含风险等级（低/中/高）、影响范围、未覆盖路径、回滚方式；完整档须给出 go/no-go 判定，遇红区、不可逆、超出授权或 go 判据不满足时停止并请求人工确认。

## 硬边界

- 编辑前检查工作区并保护用户未归属改动。
- 只在授权范围内行动；生产、权限、凭据、外部写入、红区、破坏性或不可逆操作和范围扩大先获人工确认。
- 不编造事实、命令结果或完成证据；没有本轮有效验证不得声称完成。
- 同一失败连续三次且没有有效进展时，先换策略或换粒度重试，仍无进展则停止并报告阻塞。

## 任务与协作

任务 Markdown 是可选的人读记录，可保存目标、档位、状态、验收、下一步、验证和风险；它不被解析或参与运行时判断。单 Agent 是默认路径；仅在用户明确要求或独立工作单元有明显收益时使用宿主原生协作能力。并行单元须错开写入范围，共享写入点指定唯一归属，避免并发覆盖；写入范围用项目相对路径或目录 glob 声明，一个范围是另一个的路径祖先时视为重叠，须串行或改由一人独占。

## Skill 选择

宿主只在 description 精确命中当前需求时选择一个领域 Skill。Skill 不改变授权、安全边界或证据标准。
