# LoopEngine 治理内核

## 五步循环

| 阶段 | 动作 | 退出条件 |
| --- | --- | --- |
| 获取事实 | 阅读本地规则、工作区状态和相关代码；项目内已有代码结构索引工具时先确认索引并用于结构化定位 | 已区分事实、关键假设、歧义和待决策项 |
| 做出决策 | 公开关键假设与取舍，固定目标、验收标准、非目标和风险；多种解释时不得静默选择，优先满足验收的最简单方案 | 成功标准和验证方式明确，不再存在会改变实现的歧义 |
| 执行 | 在授权范围内完成最小可验证改动 | 产物已形成，范围变化已停止并重新决策 |
| 验证 | 运行本轮有效检查，并做“主张 → 证据 → 反例 → 剩余风险”核对 | 每条验收标准都有证据或明确未验证原因 |
| 交付 | 报告变更、证据、未验证项、风险和 Git 状态 | 接手者能判断真实状态和下一步 |

## 五条硬约束
1. 编辑前检查 `git status --short`，保护用户未归属改动。
2. 只在用户授权范围内行动；红区、不可逆操作和范围扩大先获人工确认。
3. 不编造 API、字段、权限、数据、命令输出、测试或发布结果。
4. 先有本轮证据，再声称完成；失败和未验证项如实交付。
5. 风险升级时立即提高档位；完整或高风险任务必须由独立核验者审查。

## 任务确认与交付
- 新任务或任务范围发生实质变化时，首次使用工具前输出任务确认。快速档包含任务目标、影响范围、Workflow 不适用原因、成功标准和验证计划；轻量/完整档还包含主 Workflow、强制修饰器、风险等级和非目标。红区任务执行前补充修改范围、原因、验证和回滚，并等待人工确认。
- 会话结束按 `docs/templates/delivery.md` 报告结果状态、变更与影响、档位、证据、未验证项、风险、Git/worktree/分支/merge-back、后续动作和 Memory 判定；未验证、未合并或红区未确认时不得声明完成。

## 风险档位

- **快速**：只读、纯文档、低风险文案，且不改变运行时、公开契约或红区。
- **轻量**：单一范围的低风险实现，可由聚焦验证证明，不涉及安全、数据、发布、生产、跨层或外部契约。
- **完整**：红区、安全、数据库、生产、发布、高风险、跨层、外部契约、父子任务或多 Agent。

不确定时选择更高档位。快速任务发现行为变化时升级；轻量任务发现完整档位信号时停止并补齐完整流程控制。

## 停止与审查

- 目标或验收不清、权限不足、规则冲突、红区未确认、范围扩大或验证反复失败时停止。
- 所有任务在验证阶段记录主张、支持证据、已检查反例和剩余风险。
- 完整或高风险任务必须完成独立 Red Team（红队审查），保存结构化审查包并获“批准”后才能完成；审查覆盖正确性、安全与滥用、架构、测试、发布和回滚。
- `Critical` / `High` 必须修复；`Medium` 必须修复或记录问题编号、理由、责任人、关闭条件和批准者。

## 无 Skill 降级

没有 Skill 能力时，使用 `docs/templates/task.md` 记录任务，使用 `docs/templates/delivery.md` 交付；只读取命中场景的专项规则。
