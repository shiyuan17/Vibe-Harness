# Agent Collaboration

每个任务先回答五个问题：读什么、风险多高、能不能动、怎么验证、怎么交付。

## 启动门禁

- 改代码前先读项目入口文档。
- 先运行 `git status --short`，保留与当前任务无关的用户改动。
- 将任务归类为 Fast Path、Lightweight 或 Full。
- 动手前识别红区改动。
- 定义能证明成功标准的最小验证命令。

## 五条红线

1. 修改认证、权限、全局请求层、构建/发布路径、环境变量、CI 或破坏性操作前，必须先获得人工确认。
2. 不编造 API、字段、权限码、schema 或部署结果。
3. 实现 Agent 不能自我批准高风险工作。
4. 使用 worktree 时，未确认 merge-back 状态不得宣称交付完成。
5. 真实验证证据优先于信心和经验判断。

## 交付包

交付包包含摘要、影响范围、验证证据、剩余风险和工作流档位。Fast Path 任务若不改变运行时行为，可以使用精简交付包。
