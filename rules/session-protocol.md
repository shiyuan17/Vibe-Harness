# 会话协议（Session Protocol）

会话协议（`Session Protocol`）是每次 Agent 会话的启动与收尾协议。它回答两个问题：开始前是否具备安全执行条件，结束时下一位执行者是否能判断真实状态。

## 会话开始协议（Session Start Protocol）

开始执行前先完成以下检查：

- 入口阅读：阅读 `AGENTS.md`、`docs/rules/quickstart.md`、`docs/rules/agent-collaboration.md` 和本规则；命中专项场景时再读对应规则。
- 任务确认：确认任务目标、验收标准、非目标和用户限制；验收会改变行为且不清楚时先澄清。
- 工作区事实：运行 `git status --short`，识别用户未归属改动、当前分支、暂存内容和可能冲突。
- 代码上下文：若仓库存在 `.codegraph/`，理解或定位代码前先使用 CodeGraph；不可用时说明原因并回退到普通搜索。
- 风险档位：将任务归类为 `Fast Path`、`Lightweight` 或 `Full`；不确定时按更高风险档位处理。
- 红区确认：命中认证、权限、全局请求层、环境变量、CI/CD、构建发布、破坏性数据操作或目标项目自定义红区时，先说明范围、原因、验证和回滚，再等待人工确认。
- 验证计划：定义能证明成功标准的最小验证命令或人工核对来源；不能验证时先说明原因和风险。

## 会话结束协议（Session End Protocol）

每次会话结束都必须输出可核对的收尾信息，即使任务没有完成：

- 摘要：完成了什么，或本轮只做了哪些调查。
- 影响范围：改动或判断涉及的文件、模块、规则面、配置面。
- 验证证据：命令、退出码、关键输出，或明确的人工核对来源。
- 未验证项：没有验证的内容、原因、风险和建议的下一步验证。
- 风险：剩余风险、红区确认状态、外部依赖或阻塞条件。
- Git 状态：当前分支、脏文件、暂存状态；若未运行 `git status --short`，必须说明原因。
- Worktree / 分支 / merge-back 状态：是否存在独立 worktree、临时分支、未合并提交或待 merge-back 内容。
- 后续动作：下一步最小动作；没有后续动作时写“无”。

## 结束状态

- 完成：所有成功标准已满足，验证证据来自本轮最新运行或明确核对，Git / worktree / merge-back 状态已说明。
- 未完成：写清已完成、未完成、下一步最小动作，并在需要恢复时使用 `handoff` 规则或模板。
- 阻塞：写清阻塞原因、需要谁决策、缺少什么信息或外部状态，以及解除阻塞后的第一步。
- 中断：写清当前阶段、已修改文件、未保存或未验证风险、恢复入口；不得把中断状态说成完成。

## 禁止项

- 不用“应该可以”“基本完成”“看起来没问题”替代验证证据。
- 不省略失败命令、退出码、关键错误或未验证项。
- 不把未 merge-back 的 worktree、未处理冲突、未确认红区或未通过验证的工作声明为完成。
