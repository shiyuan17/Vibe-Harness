# 任务生命周期

本规则定义从需求到交付的可选产物。快速路径（`Fast Path`）可以简化，但不能跳过红区、验证或用户改动保护。

## 阶段

| 阶段 | 目标 | 最小产出 |
| --- | --- | --- |
| 澄清（`Clarify`） | 消除目标、验收、非目标歧义 | 任务启动信息 |
| 规格（`Spec`） | 固定行为、契约和边界 | 规格说明 |
| 计划（`Plan`） | 拆成可执行步骤 | 实施计划 |
| 任务拆分（`Task`） | 建立父任务 / 子任务执行单元 | `task.json` 或任务卡 |
| 执行（`Execute`） | 在边界内实现 | diff 和证据 |
| 验证（`Verify`） | 证明成功标准 | 命令、截图、日志或人工核对 |
| 审查（`Review`） | 独立检查风险 | 审查包 |
| 交接（`Handoff`） | 保留续接状态 | 交接记录 |

## 5 分钟子任务

子任务应能在 5 分钟内判断完成、未完成或阻塞。必须包含：

- 执行模式：`Execution Mode: goal`
- 时间盒：`Timebox: <= 5 minutes`
- 目标 / 验收标准 / 非目标
- 停止条件
- 验证命令
- 回滚方案
- 写入范围、禁止动作和依赖 / 冲突关系
- 证据

拆分时先判断任务模式：

- 单一目标、单一写入范围、一次验证闭环即可完成时，保持 `single`。
- 命中多 agent、多个 worktree、完整流程（`Full`）、高风险、多个可独立审查交付物，或写入范围可并行拆分时，建立 `parent` / `child`。
- child 是最小可审查闭环，不是单个机械步骤；不能把写测试、改一行或运行命令单独拆成 child，除非它本身可交付、可验收。
- child 应能在约 5 分钟内完成或暴露阻塞；无法判断写入范围、依赖或冲突时，回退澄清或串行。

## 多 Agent

- 实现、集成、审查角色分离。
- 并行子任务必须声明 `writeScope`、`parallelSafety`、`humanConfirmation` 和冲突关系。
- 并行子任务必须声明依赖 / 冲突关系，父任务负责检查依赖顺序和最终集成验证。
- 无法判断写入范围是否重叠时，回退串行。
- 高风险默认启用独立审查。
