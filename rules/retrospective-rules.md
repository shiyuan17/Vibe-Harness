# 复盘规则（Retrospective）

复盘规则（`Retrospective`）用于把返工、事故、重复失败和规则缺口转化为可执行改进。复盘不是责备个人，而是更新规范、模板、测试或自动化，防止同类问题再次发生。

## 触发条件

- 同一类错误重复出现。
- 验证、审查或发布发现本可由规则提前阻止的问题。
- Agent 因目标、边界、验收或状态不清而返工。
- 安装器、校验器、模板或 workflow 暴露治理缺口。

## 必填字段

- 触发原因和影响范围。
- 失败模式：具体发生了什么，不写抽象标签。
- 根因：目标、指标、边界、模板、流程、工具或自动化哪一层缺失。
- 规则/模板/测试/脚本改进项。
- 验证方式：如何证明改进能防止复发。
- 负责人和完成标准。

## 输出

- 更新后的规则、模板、schema、测试或 issue。
- 若无法立即修复，写入交接记录，并说明下一步最小动作。

## 完成标准

- 至少产生一个可执行改进，不只写经验总结。
- 改进项有验证命令或人工核对方式。
- 不把“提醒 Agent 注意”作为唯一防线。
