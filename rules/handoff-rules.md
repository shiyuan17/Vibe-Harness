# 交接规则（Handoff）

交接规则（`Handoff`）保证任务暂停、转交或带未完成项结束时状态可恢复。普通会话启动与收尾以 `session-protocol` 为单一来源；handoff 是恢复型交接协议，不替代每次会话结束的基础输出。

## 触发条件

- 工作未完成但需要暂停、转交或等待人工决策。
- 验证失败、冲突合并、红区确认缺失或外部契约不一致。
- 多 Agent 子任务完成后需要交还父任务汇总。
- 交付时存在未验证项、剩余风险或后续动作。

## 必填字段

- 当前目标、阶段、状态、终结状态。
- 已完成事项、未完成事项和下一步最小动作。
- 修改过或需要关注的文件。
- 验证证据：命令、退出码、关键输出或人工核对来源。
- Git / worktree 状态：分支、脏文件、暂存状态、merge-back 状态。
- 恢复提示：从哪个文件、命令、任务或分支继续。

## 完成标准

- 下一位执行者无需读取聊天历史也能恢复。
- 未完成项都有负责人、阻塞原因或下一步动作。
- 不把未验证工作标记为完成。
- 高风险或红区工作明确人工确认状态。

## 禁止项

- 不写“基本完成”“看起来可以”这类无法验证的状态。
- 不省略失败命令、退出码或关键错误输出。
- 不把孤立 worktree、未合并分支或未处理冲突当作完成状态。
