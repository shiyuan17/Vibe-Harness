# 快速路径工作流（`Fast Path`）

用于纯文档、只读、测试-only 或低风险文案改动。快速路径（`Fast Path`）只减少流程重量，不减少用户改动保护、红区确认和验证证据。

## 阶段目标

快速处理不会改变运行时行为、不会触碰红区、不会改变公共契约的任务，并保留可追溯证据。

## 输入内容

- 用户请求或审查范围。
- 当前 `git status --short`。
- 命中的入口规则、模板或文档。
- 最小验证命令或人工核对方式。

## 输出内容

- 变更摘要或只读结论。
- 快速路径适用原因。
- 验证证据：命令、退出码、关键输出，或人工核对项。
- 未验证项与剩余风险。

## 完成标准

- 确认未触发安全、数据库、发布、生产、红区、跨层或外部契约。
- 目标文件或审查范围已覆盖。
- 验证证据足以证明本次目标，不使用历史输出代替。
- 若发现范围扩大，停止并升级到轻量流程（`Lightweight`）或完整流程（`Full`）。

## 常见异常

- 文档改动实际影响安装器、hook、CI 或生成模板。
- 只读审查发现需要代码修改。
- 验证命令不存在或项目未提供治理检查。

## 异常处理方式

- 触发运行时行为、红区或发布面时立即升级，不继续按快速路径交付。
- 需要代码修改时新建或更新 Task Intake，重新选择 workflow tier。
- 验证命令缺失时记录人工核对项和缺失原因，并建议补自动化检查。
